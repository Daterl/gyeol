# target_extract — 지향 프로필 추출 프롬프트 계약

**상태: 문서만 있고 배선되지 않았다.** `lib/target_profile.js` 는 현재 **모델을 호출하지 않는다**.
결정적 규칙(`docs/specs/10-target-profile/spec.md` 3·4절)만으로 `TargetProfile` 을 만든다.
이 문서는 그 자리를 모델로 바꿀 때 **모델이 지켜야 하는 계약**이다. 배선은 별도 이슈로 남긴다(PR 본문 참조).

## 왜 지금 모델을 안 쓰는가

- 자연어 경로는 `docs/intent.md` C2 가 말한 **항상 성공하는 바닥**이다. 바닥이 모델 가용성에 의존하면 바닥이 아니다.
- ref 경로는 **숫자 집계**다. 캡션 길이 p50 을 모델에게 세게 하는 것은 더 비싸고 덜 정확하다.
- `#6` 의 A1 실측(서버 함수 시간 상한)이 아직 없다. 측정 전에 모델 호출을 크리티컬 패스에 넣지 않는다.

## 모델을 붙일 때의 계약

### 입력

| 경로 | 모델에게 주는 것 | 절대 주지 않는 것 |
|---|---|---|
| 자연어 | 사용자 원문 1개 | 다른 사용자의 입력, 스냅샷 |
| ref 스냅샷 | `{shortCode, caption, type, child_count, timestamp}` 배열 | 좋아요·댓글·도달·프로필 사진·URL |

### 출력

`schemas/target_profile.md` 의 `TargetProfile` **그대로**. 모델 출력은 예외 없이 `validateProfile(v,'target')` 을 통과해야 하며,
통과하지 못하면 **결정적 규칙 경로로 떨어진다**(에러가 아니다). `#9` 의 `analysis_source: "heuristic"` 과 같은 방식이다.

### 모델이 하면 틀린 것

1. **근거 없는 필드를 채우는 것.** 모르면 필드를 생략한다. 생략은 실패가 아니라 정답이다(P3).
2. `evidence` 를 만들어내는 것. `user_text.ref` 는 **입력에 실제로 있는 문자열**이어야 하고, `ig_post.ref` 는 **스냅샷에 있는 shortCode** 여야 한다.
3. `kind:"rule"` 만 붙인 항목을 내는 것. 규칙만으로 채운 항목은 프리셋이다.
4. 사진에 없는 장소·인물·시간·감정을 쓰는 것.
5. 좋아요·도달·조회 수를 프로필에 넣거나 예측하는 것.
6. 준비되지 않은 계정의 URL 을 받고 **다른 계정 스냅샷으로 답하는 것.**
7. `completeness` 를 "그럴듯하게" 올리는 것. `completeness` 는 채운 항목 수를 센 값이며 자평 점수가 아니다.

### 사진만 입력

**이 프롬프트를 쓰지 않는다.** 사진만 입력은 `TargetProfile` 이 아니라 `PhotoPlan` 을 만들고,
그 재료인 `PhotoAnalysis` 는 `#9` 가 **사진 1장당 호출 1회**로 만든다. 여기서는 이미 나온 분석을 합치기만 하므로 모델 호출이 0회다.
