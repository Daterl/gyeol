상태: **기획 제안 / 기능 미구현**. [HTML 기획서](../plans/instagram-product-expansion.html) · [엄브렐라 #65](https://github.com/Daterl/gyeol/issues/65).
기준 코드: develop `ab01d4205b1cd2dd6177bc11b15c5f4954346b7b`.
사용자 요청 순서: 리서치 → 수정·보완 플래닝 → 설명식 엄브렐라. 이번에는 서브태스크를 생성하지 않는다.

**확정 결정 추가:** 수집 도구는 **`apify/instagram-scraper`**, 대상은 **공개 계정·공개 게시물만**이다. 비공개 계정 조회는 제외한다. [ADR-0006](../adr/0006-apify-public-instagram.md). 앱 전체는 **모바일 우선**으로 설계한다. [ADR-0007](../adr/0007-mobile-first-experience.md). 나머지 확장 항목은 제안/미구현 상태이며 제공자 선정은 실수집 완료를 뜻하지 않는다.

## 1. 리서치

### 조사 범위와 한계

Instagram 공식 도움말의 실제 본문(데스크톱·iPhone 안내), Meta 공식 발표·개발자 문서, Apify 제공자 문서와 현재 코드를 대조했다. Help/개발자 문서는 웹 수집 오류가 있어 Chrome에서 직접 읽었다. 도움말에 자동 표시되는 Meta AI 답변은 근거에서 제외했다.

초기 문서 작성 때에는 개인 계정 실사례를 조사하지 않았다. 이후 사용자가 제공한 계정에서 공개 프로필, 로그인 후 게시물 상세 3개와 하이라이트 일부를 브라우저로 열람했고 [#65](https://github.com/Daterl/gyeol/issues/65)에 범위와 관찰을 기록했다. 이는 개인화 생성 품질·제공자 수집·네이티브 앱 작성 화면의 검증이 아니다. 유료 수집·모델 호출은 실행하지 않았다. 기능별 국가·계정·앱 버전 차이는 실기기 확인이 남아 있다. 사례 하나의 문체를 전체 사용자에게 일반화하지 않는다.

기존 기획·HTML·`fixtures/ig_snapshot.json`과 `fixtures/ref_snapshot.sample.json`은 제한된 MVP의 근거다. 그 자료와 단일 브랜드 샘플만으로 일반 사용자의 한 장·캐러셀·스토리 경험을 검증했다고 볼 수 없다. 기존 기획의 “대부분 비공개”, 경쟁 도구 부재 등은 이번 조사로 확인한 사실이 아니며 사용자·경쟁 조사 가설로 남긴다.

### 확인한 플랫폼 동작 → 제품에 주는 의미

| 구분 | 확인한 사실 | GYEOL의 기획 판단 |
|---|---|---|
| 한 장 | 사진 게시에는 캡션·위치·대체 텍스트가 있고 음악 추가 경로도 있다. [S1] | 한 장도 정상 입력. 순서 점수 대신 말의 양·비움·맥락·게시 준비를 돕는다. |
| 여러 장 | 캐러셀은 최대 20개 사진/동영상으로 구성된 **한 게시물**이다. 위치는 게시물 단위, 사람 태그는 개별 미디어에 붙일 수 있다. [S2] | 2장부터 캐러셀. 게시물과 사진을 구분하고 첫 장·내부 순서를 따로 다룬다. GYEOL 초기 입력은 사진만 유지한다. |
| 캡션 | 공식 iPhone 도움말에는 단일 캡션과 사진/동영상별 복수 캡션 선택이 있다. 데스크톱 안내는 공통 캡션 중심이다. [S2] | “캐러셀은 캡션 하나뿐”으로 고정하지 않는다. 게시물 공통/항목별 초안을 구분하고 대상 앱 지원을 확인한다. |
| 게시 후 편집 | 현재 도움말은 게시 후 순서 변경·항목 삭제와 캡션·위치·태그 편집을 안내하며, 새 항목 추가는 불가하다고 설명한다. [S2] | 단순 순서 이동만을 독점 기능처럼 설명하지 않는다. 근거 있는 선택·개인 문체·맥락 연결이 가치다. |
| 음악 | Meta는 사진에 이어 사진 캐러셀의 음악 추가를 발표했다. Collabs는 사람 태그와 다른 공동 작성 기능이다. [S3] | 곡 메모·분위기 제안과 실제 라이브러리 곡 선택을 구분한다. 태그와 공동 작성도 분리한다. |
| 스토리 | 스토리는 일반적으로 24시간 후 사라지고 하이라이트로 남길 수 있다. 링크·위치·음악·질문·투표 등의 스티커가 있으며 가용성은 다를 수 있다. [S4, S5] | 시간 순서의 프레임과 텍스트 오버레이·상호작용 계획이 필요하다. 정적 이미지에 그린 스티커는 실제 링크/투표가 아니다. |
| 본인 계정 연결 | Instagram Login API는 비즈니스·크리에이터용이며 Facebook 페이지 연결은 필수가 아니다. 문서는 광고·태그 접근 제한도 명시한다. [S6] | 공식 API는 비교 조사 자료다. 확정 수집 경로는 Apify이며 OAuth 연결을 이번 범위에 추가하지 않는다. |
| 게시물 URL 수집 | Apify Instagram Scraper의 `directUrls`는 `/p/` 게시물 URL을 받는다. Post Scraper는 사용자 이름 중심의 별도 Actor다. [S7] | `apify/instagram-scraper` 사용 확정. 기존 계정 URL 입력의 문구만 바꿔서는 동작하지 않으며 반환 필드는 실증이 필요하다. |
| 수집 제한 | 제공자는 공개 로그아웃 화면 기준이며 비공개 계정 수집을 지원하지 않는다고 설명한다. 예제의 `musicInfo`는 모든 사진 게시물에서 보장되는 필드가 아니다. [S8] | 부분 성공과 수동 보완을 기본 설계한다. 미수집을 “없음”으로 해석하지 않는다. |

홈에서 보는 **피드**, 내 계정의 **프로필 그리드**, 한 게시물 안의 **캐러셀 순서**는 다른 개념이다. 이번 기획의 그리드는 내 게시물 조합을 미리 보는 기능이며 홈 피드 노출 순서를 제어하거나 성과를 예측하는 기능이 아니다. 프로필 그리드 재배열의 현재 계정별 네이티브 지원은 직접 검증하지 않았으므로 지원/미지원을 단정하지 않는다.

## 2. 수정·보완 플래닝

### 제품 한 문장

**올릴 사진과 내 기록을 바탕으로, 한 장·캐러셀·피드·스토리에 맞는 구성과 말을 근거와 함께 준비한다.**

사진을 바꾸지 않고 사용자의 선택을 돕는다. 사진만으로도 한 화면에서 시작하고, 내 기록·장소·상황·노래·태그는 선택적으로 펼친다. 링크 입력을 새로운 필수 관문이나 다단계 가입 흐름으로 만들지 않는다.

### “내 기존 게시물로 알려주기”

1. **기본 선택: 본인 게시물 링크 추가.** 처음에는 공개 사진 게시물 `/p/…/` 링크 1–5개를 제안한다. 이는 Instagram 제한이 아닌 수집량·확인 부담을 줄이기 위한 제품 초안이다. 계정 전체 분석은 별도 고급 경로로 남긴다.
2. 수집 전 외부 제공자·처리 항목·보관 범위·예상 사용량을 안내한다. 이번 문서는 실제 전송 동의를 대신하지 않는다. 개발 단계 실호출은 비용·환경 확인 후 진행한다.
3. 게시물별로 대표 사진, 캐러셀 내부 사진, 원문 캡션, 출처·수집 시점과 필드별 상태를 보여준다. 사용자는 포함할 게시물을 확인하고 잘못 가져온 정보를 고친다. 링크 입력은 계정 소유권 인증이 아니므로 “본인 계정 인증 완료”라고 표시하지 않는다.
4. **비공개로 확인된 계정은 조회 대상에서 제외**하고 지원 범위를 안내한다. 공개 자료의 삭제·차단·만료·미지원은 비공개와 구분한다. 성공한 게시물과 편집을 유지하고 재시도 가능한 항목만 재시도한다. 사용자가 별도로 **사진 + 원문 캡션 직접 넣기**를 선택할 수 있지만 비공개 계정 조회 결과로 표시하지 않는다. 직접 넣은 사진도 게시물별로 묶어 원래 순서를 보존한다.
5. 샘플이 부족하면 “이 게시물에서 확인한 특징”으로 범위를 좁힌다. 링크 1개로 장기 문체·전체 계정 취향을 확정하지 않는다. 텍스트가 없으면 문체는 미관측이다.

URL은 HTTPS·허용 호스트·게시물 경로로 검증하고 쿼리/추적 파라미터를 정리해 shortcode 기준으로 중복 제거한다. 임의 URL fetch·내부 주소·리다이렉트 우회·인증 정보 포함 URL을 차단하고 응답 크기·미디어 타입·시간·비용 한도를 둔다. Instagram 로그인 쿠키를 요구하지 않는다. 취소 후 늦은 응답은 기존 편집을 덮지 않는다. 사진 속 글·수집 캡션은 분석 대상 데이터이며 모델 지시로 실행하지 않는다.

### 발행 형태별 경험

| 형태 | 입력과 구성 | 결과와 비움 |
|---|---|---|
| 한 장 | 사진 1장. 캡션·장소·상황은 선택. | 사진 한 장의 캡션/캡션 없음, 근거, 대체 텍스트 초안. 불필요한 순서·도입/전환/결말을 생성하지 않는다. |
| 캐러셀 | 사진 2–20장. 커버·내부 순서·크롭 미리보기. | 공통 캡션 또는 항목별 캡션 초안, 게시물 위치, 사진별 태그 메모. 캡션 비움은 사진 삭제와 다르다. |
| 프로필 그리드 | 기존 게시물과 새 게시물 묶음. 캐러셀은 대표 이미지 한 칸. | 게시물 단위 배치 시뮬레이션. 캐러셀 내부 순서는 별도 편집. 고정·숨김·실제 배열을 사용자가 확인하며 시간순 수집을 실제 그리드라고 단정하지 않는다. |
| 스토리 | 사진 기반 프레임 1개 이상. 초기 세션 상한은 기존 자원 한도에 맞춰 20개 제안. | 프레임 순서·짧은 오버레이·여백·스티커/곡 메모·하이라이트 이름 제안. 최종 스티커·음악 적용은 Instagram에서 한다. |

한 장에 캡션이 필요하면 채운다. 기존 “최소 한 슬롯은 비움” 시연 기준을 단일 사진에 강제하지 않는다. 타이틀은 작업의 제목이며 Instagram에 별도 타이틀 필드가 있는 것처럼 표현하지 않는다. 스토리 9:16은 제안 미리보기 규격이며 강제 플랫폼 입력 조건으로 설명하지 않는다. 크롭·스토리 레이아웃은 비파괴 미리보기부터 시작하고 원본 파일을 변경하지 않는다.

### 장소·컨텍스트·음악·태그

| 요소 | 사용자가 주는 것 | 제안/출력 원칙 |
|---|---|---|
| 장소 | 공개하고 싶은 장소 이름, 선택한 후보 | 사진만 보고 정확한 장소/GPS를 확정하지 않는다. 실제 Instagram 장소 엔티티 연결은 앱에서 확인한다. |
| 컨텍스트 | 언제/어떤 상황/왜 남기는지, 말하고 싶은 것·숨길 것 | “어제 친구와” 같은 사실은 사용자 입력이나 명시된 출처가 있을 때만 쓴다. 사람의 신원·관계·감정을 사진으로 단정하지 않는다. |
| 음악 | 사용자가 고른 제목·아티스트 또는 원하는 분위기 | 초기에는 곡 메모와 검색어 제안. 실카탈로그를 조회하지 않은 곡 ID·이용 가능성은 만들지 않는다. 음원·가사 파일은 내보내지 않는다. |
| 태그 | 해시태그, @언급, 사진 속 사람 태그, 공동 작성자를 각각 선택 | 선택한 의미를 유지한다. 자동 태그·무단 공동 작성 요청·해시태그 대량 생성은 하지 않는다. |
| 대체 텍스트 | 사용자 수정 가능한 사진 설명 | 캡션과 다른 접근성 필드. 사진에서 관찰되는 내용 중심으로 작성한다. |

근거는 **사진 관찰 / 수집된 게시물 메타데이터 / 사용자 설명 / 모델 제안**으로 구분한다. 원문과 사용자의 수정본을 별도로 보존한다. 미수집·실제로 없음·미확인을 구별하고, 개인화에서 제외할 기록은 제거할 수 있어야 한다. 초기 제안은 세션 범위 사용이며 별도 영구 계정 학습은 하지 않는다. 제공자 보관 정책·캐시 TTL·삭제 방식은 실수집 착수 전에 확정한다.

### 기존 계약을 확장하는 최소 범위

새 범용 콘텐츠 엔진을 만들지 않는다. 기존 `photo_id`, 근거, 편집 store, 취소·재시도·내보내기를 재사용한다. 첫 계약 합의에서는 발행 형태, 게시물 ID와 미디어 ID의 관계, 캡션의 적용 단위, 선택 맥락과 출처만 결정한다. 네 형태의 모든 필드를 첫 PR에 미리 구현하지 않는다.

공유 수정 후보는 `schemas/`, `lib/contracts.js`, `lib/interaction.js`, `src/types/contracts.ts`, 요청/응답 fixtures다. 이후 입력·프로필 분석·순서 제안·생성·편집·내보내기의 소비자를 함께 추적한다. 새 계약 버전을 명시하고 기존 3–20장 샘플/편집본을 읽는 경로를 유지한다. 형태 전환은 초안을 보존하고, 복수 캡션을 지원하지 않는 대상에 내보낼 때 자동 합치기/삭제 대신 사용자에게 선택을 요청한다.

### 진행 가능한 순서 — 아직 서브태스크가 아니다

**A. 단위·경계 정리 → B. 한 장/캐러셀 + 링크·수동 보완 → C. 그리드·게시 맥락 → D. 스토리.**

- **A / 공동:** 기존 D3–D5와 새 발행 단위·1/2장·비움 기준의 차이를 합의한다. 1·2·20·21장 및 구버전 fixtures로 계약을 먼저 확인한다.
- **B / diego + enzo:** 한 장·캐러셀의 입력부터 내보내기까지 완결한다. 지정 Apify Actor로 공개 단일/캐러셀, 삭제, 부분 성공, 중복, 캡션 없음을 실증 후 연결한다. 비공개 제외는 fixture로 확인하며 비공개 계정 실수집은 하지 않는다. 수집 게이트가 남아도 수동 보완 경로는 진행 가능하다.
- **C / diego 중심, 분석 협업 enzo:** 게시물 묶음 그리드, 장소·상황·음악 메모·태그 구분을 연결한다. 기본 맥락 입력은 B에도 포함하고 C에서는 결과별 편집과 내보내기를 완성한다.
- **D / 공동:** 사진 기반 스토리 프레임과 네이티브 스티커 인계부터 검증한다. 동영상/릴스 편집, 음악 재생, 자동 게시·예약 발행은 별도 범위이며 이번 계획에 넣지 않는다.

기획 확인과 구현 완료를 구분한다. 자동 게시·영구 계정 연결·음원 처리 없이도 위 초안 준비 경험은 성립한다. 기존 제출 마일스톤에 확장 전체를 강제하지 않는다.

전체 흐름은 모바일 웹에서 먼저 설계한다. 390px을 기준으로 360px·430px 경계를 확인하고, 터치·키보드·사진 선택·캡션 편집·순서 이동·내보내기를 실제 모바일에서 검증한다. 데스크톱은 같은 기능을 넓은 화면으로 확장한다. 현재 HTML의 반응형 확인은 앱의 모바일 우선 적용 완료가 아니다.

### 인수 시나리오

1. 사진 1장만으로 시작하고 개인화·순서가 없다는 이유로 막히지 않는다. 2장은 캐러셀로 끝까지 처리된다. 20장 수용·21장 거절과 기존 3–20장 흐름도 유지된다.
2. 같은 캐러셀 URL을 다른 추적 쿼리로 넣어도 하나이며, 자식 사진 순서/출처/원문 캡션을 보존한다. 미지원 미디어는 삭제 없이 미지원으로 표시한다.
3. 링크 일부가 실패해도 성공한 기록과 사용자의 수정·사진 선택을 잃지 않고 수동 입력으로 이어진다. 취소된 응답이 복귀하지 않는다.
4. 사용자 입력 없는 장소·시간·인물 관계와 미확인 음악을 사실처럼 만들지 않는다. 캡션이 없는 샘플로 문체를 학습했다고 표시하지 않는다.
5. 캐러셀 한 개는 그리드 한 칸이다. 내부 사진 이동과 게시물 이동이 섞이지 않는다. 형태 전환/다시 생성/내보내기에서 초안·비움 상태가 보존된다.
6. 스토리 결과는 정적 제안과 실제 작동하는 스티커를 구분한다. 음원이나 연결되지 않은 링크가 적용됐다고 표시하지 않는다.
7. 실제 대상 앱에서 공통/항목별 캡션·장소·태그·음악·스토리 인계를 확인하고, 불가한 조합에는 명시적 수동 경로를 제공한다.

## 3. 엄브렐라 운영

기존 #22의 D3(구성)·D5(말/비움)·D6(개인화)를 출발점으로 한 **별도 확장 기획 엄브렐라**다. 사용자 요청으로 HTML 재작성(C8)을 이번 문서 작업에 한해 수행한다. 라이브 수집(C1), 공식 연결(C7), 입력 수와 발행 단위는 제안이며 기존 `docs/intent.md`나 승인된 ADR을 조용히 바꾸지 않는다.

담당 diego.yoon, 입력 이해·수집 협업 enzo.cho. GitHub Project #2의 검토 상태에 두고 설명·출처·HTML·남은 게이트를 연결한다. 이번에는 하위 이슈, 자동 발행, 제품 코드, Production 변경을 만들지 않는다. 기획 산출물 완료 후에도 실제 기능 확장 엄브렐라는 열린 상태를 유지한다.

실행을 분해할 때만 각 AI Session에 소유 파일, 공유 계약, 선행 산출물, 검증 증거를 붙인다. 범위 관계와 실행 의존성은 별도 기록하고, 엄브렐라 종료를 자식 착수 조건으로 삼지 않는다.
