## 1. 제품 한 줄

> **올리고 싶은 사진 여러 장을 넣으면, 어떤 순서로 / 뭐라고 열고 / 어디에 말을 붙일지를 근거와 함께 제안한다.**

- 제품명은 **`결 GYEOL`** 로 고정. (표기 그대로 쓴다.)
- 우리는 사진을 **바꾸지 않고 고른다.** 보정·필터·생성은 하지 않는다.
- 결과물은 언제나 **초안**이고 최종 저자는 사용자다.

## 2. 1차 타깃

> **부계(부계정)를 운영하는 20대 일상 기록러.**

- 본계는 관리가 피곤해서 부계를 팠는데, 부계도 슬슬 정리하고 싶어진 사람.
- 이 층에는 경쟁 도구가 서 있지 않다 — Later·Planoly·Preview·Buffer 는 전부 1인 브랜드/소상공인을 정조준한다.
- **부계는 대부분 비공개다.** 그래서 "내 계정을 읽어오는 것"이 주 경로가 될 수 없고, 이게 제품 구조를 결정했다.

## 3. 해결할 문제

> 사진 15장을 찍어 놓고 **"이걸 어떤 순서로 올리지"** 에서 멈춘다.

- 지금은 갤러리에서 한참 스크롤하고, 몇 장을 지웠다 되살리고, 캡션을 썼다 지운다.
- 기존 도구는 **한 장을 예쁘게 만들거나(보정)** **캡션을 대신 써주는 것(생성)** 뿐이다. **여러 장 사이의 순서**를 정해주는 도구를 조사 범위에서 찾지 못했다.
- 그리고 대신 써준 캡션은 AI 티가 난다 — 한국어 사용자는 이걸 이미 식별한다.

## 4. ★ 9/20 자정까지 반드시 동작해야 하는 것

### 4-1. 냉정한 판단 — F1·F2·F3 를 3.5일에 다 제대로 만들 수 있는가

**답: 못 한다.** 근거를 적는다.

| 기능 | 원래 범위 | 3.5일 추정 | 판정 |
|---|---|---|---|
| **F1** 두 축 프로필 (지향 + 현재 + 합성) | 입력 경로 5개(내 인스타 URL / ref 인스타 URL / 레퍼런스 사진 업로드 / 자연어 / 내 사진 업로드) + Apify 수집 + 3종 프로필 추출 + 합성 규칙 + 간극 목록 | **1.5일+** (원재 단독) | **깎는다** |
| **F2** 순서 제안 | 사진 N장 비전 분석 + 순서 결정 + 자리별 근거 | **1일** (원재 단독) | **안 깎는다** |
| **F3** 타이틀 + 캡션 + 비움 | 프롬프트 + 결과 화면 전체 + 3상태 + 근거 UI + 내보내기 | **1.5일** (디에고 단독) | **거의 안 깎는다** |

원재 몫만 2.5일이다. 여기에 **스키마 합의 · 첫 연결(mock 끄기) · 배포 · 데모 리허설**이 더 붙는데 이건 두 사람 공동이라 병렬화가 안 된다. 3.5일에 안 들어간다.
**그래서 F1 을 깎는다.** F2 와 F3 는 제품의 정체성이라 깎으면 다른 물건이 된다.

## 5. ★ 예선이 온라인 투표라는 사실이 스코프에 주는 영향

**투표자는 심사위원이 아니라 같이 출전한 일반 참가자다.** 이 한 문장이 우선순위를 바꾼다.

### 5-1. 무엇이 표를 버는가

| # | 표를 버는 것 | 그래서 무엇을 한다 |
|---|---|---|
| **V1** | **10초 안에 "무슨 제품인지" 이해되는 것** | 한 문장으로 말한다 — *"사진 여러 장 넣으면 올릴 순서를 정해줍니다."* 두 축·합성·간극은 **설명의 2번째 문장**이지 첫 문장이 아니다 |
| **V2** | **결과 화면 스크린샷 1장의 임팩트** | **결과 화면이 제품이다.** 투표 페이지에 걸릴 이미지 1장을 기준으로 화면을 다듬는다 (D3~D5) |
| **V3** | **직접 눌러볼 수 있는 링크** | 배포가 기능보다 먼저다 (4-4 순번 0). **로그인이 없는 것이 여기서 유리하게 작동한다** — 이건 원래 MVP 규율로 뺀 것인데 투표 맥락에서 이득이 됐다 |
| **V4** | **눌렀을 때 자기 사진 없이도 결과가 보이는 것** | **샘플 원클릭이 필수다** (D2). 사진을 15장 고르라고 요구하면 대부분 거기서 닫는다 |
| **V5** | **기억에 남는 반직관적 주장 1개** | **"다 채우지 않는다. 비움도 결과다."** 조사한 모든 캡션 도구가 캡션을 반드시 생성한다 — 여기서 갈라진다. 다만 5-3 의 리스크가 있다 |

### 5-2. 무엇이 표를 못 버는가 — 그래서 뒤로 민다

- **스키마 설계의 정합성, 불변식 8개, R&R 경계 문서.** 전부 본선·심사 자산이다. 투표자는 레포를 안 연다. → 만들되 **깎아서 만든다**(C4).
- **파이프라인의 깊이.** "Apify 로 실시간 수집합니다"는 투표 페이지에서 한 줄 이상 못 얻는다. 75초는 잃는다. → C1.
- **문서 분량.** 기획서가 991줄이라는 사실은 표가 되지 않는다. → C8.

### 5-3. 투표 맥락에서 새로 생긴 리스크

**"비움"이 성의 없음으로 읽힐 수 있다.** 심사위원에게는 "근거 있는 절제"로 읽히는 것이 투표자에게는 "캡션을 덜 만들었네"로 읽힐 수 있다.
→ 대응: **비운 자리를 빈칸으로 두지 않는다.** 비움 카드에 **근거 문장 + `[그래도 채우기]` 버튼**을 반드시 붙인다(D5). 빈칸과 "의도적으로 비웠고 이게 근거입니다"는 화면에서 완전히 다르게 보인다.

## 6. 안 하는 것

### 6-1. 원래부터 안 하는 것 (MVP 규율 — `pivot/BRIEF.md` 4항)

계정/로그인 · 결제 · 팀 협업 · 예약 발행 · **실제 인스타 자동 게시** · 사진 보정/필터/생성 · 해시태그 대량 추천 · 인게이지먼트 예측 점수 · 게이미피케이션(출석/점수/랭킹).

이유 3개만 적는다.
- **실제 자동 게시**: 게시 권한은 Meta 앱 심사 + 비즈니스 인증이 필요하고 **일정 안에 승인이 안 난다.** 우리는 게시하지 않으므로 심사 자체가 필요 없다.
- **인게이지먼트 예측 점수**: **근거를 댈 수 없다.** P2(모든 판단에 근거)와 정면 충돌한다. 이건 "나중에"가 아니라 원칙적으로 안 하는 쪽이다.
- **게이미피케이션**: 점수와 연속 기록은 "매일 올려라"는 압력이고, 그건 큐레이션의 반대다.

**이 목록은 이슈로도 만들지 않는다.** 만들면 그 자체가 나중에 "해야 할 일"로 읽힌다.

### 6-2. 3.5일이라서 추가로 자른 것

## 7. 성공 판정 기준

### 7-1. 제출 시점 (9/20 24:00) — 전부 예/아니오로 답한다

4-3절의 **D1~D6 이 그대로 판정 기준이다.** 하나라도 "아니오"면 그 항목은 제출물 설명에서 언급하지 않는다 — **없는 기능을 있는 것처럼 쓰는 것이 실패 조건이다.**

### 7-2. 예선(온라인 투표) 통과 판정

- **관측 가능한 기준: 상위 50팀 안에 든다.**
- 우리가 통제할 수 있는 선행 조건은 **D1(링크) + D2(샘플 원클릭) + V2(결과 화면 스크린샷 1장)** 셋뿐이다. 나머지는 통제 밖이다.
- ⚠️ **득표수 목표를 숫자로 정하지 않는다.** 전체 참가 팀 수를 확인하지 않았으므로 근거가 없다.

### 7-3. 제품이 살아 있다는 판정 (기능 차원)

| # | 기준 | 어떻게 관측하나 |
|---|---|---|
| **S1** | **순서가 근거와 함께 나온다** | 15슬롯 전부의 근거를 펼쳐 봤을 때, 근거가 전부 설계 규칙(`kind:"rule"`)뿐인 슬롯이 **0개**다. 하나라도 있으면 그건 개인화가 아니라 규칙 적용이다 |
| **S2** | **비움이 실제로 나온다** | 15슬롯 중 캡션이 비워진 슬롯 ≥ 1, 그리고 그 자리에 근거 문장이 있다 |
| **S3** | **프로필이 결과를 실제로 바꾼다** | 같은 사진 세트를 프로필 2벌로 돌렸을 때 **순서 배열이 다르다**. 같으면 프로필이 실제로는 안 쓰이고 있는 것이다 |
| **S4** | **없는 사실을 말하지 않는다** | 데모용 사진 세트 1벌의 캡션을 사람이 **전수 대조**해, 사진에 없는 장소·인물·시간이 들어간 캡션이 **0개**다 |

**S3 이 가장 중요하다.** S3 이 깨지면 우리는 "스타일 프리셋 적용기"이고, 그건 제품이 다른 물건이 됐다는 뜻이다.

## 8. ★ 미검증 가정 — 개발 중에 깨지면 치명적인 3개

기획서 1-4절에 미검증 가정이 18개(U1~U18) 있다. **그중 3.5일 개발 중에 깨지면 복구할 시간이 없는 것 3개**만 골랐다.

### A1. 서버리스 함수의 실행 시간 제한 안에 사진 15장 분석이 끝난다

| | |
|---|---|
| **왜 치명적인가** | 깨지면 **D2·D3 가 동시에 죽는다.** 사진 15장을 비전 모델로 분석하는 데 얼마나 걸리는지 **아직 실측하지 않았다**(`30-rnr.md` 3-2절도 "미검증"으로 표기). 배포 환경의 함수 실행 시간 상한도 **확인하지 않았다** — 플랜별로 다르다. 로컬에서 되는데 배포에서 타임아웃 나는 형태로 터지고, 그때는 이미 마지막 날이다 |

## 9. 이 문서의 한계

1. **전체 참가 팀 수와 투표 방식의 세부(1인 몇 표인지 등)를 확인하지 않았다.** 5절의 전략은 "투표자 = 일반 참가자"라는 사실 하나에서만 도출했다.
2. **공식 심사 기준·배점을 확인하지 못했다**(U8). 본선 전략은 확보된 뒤에 다시 쓴다.
3. **A1 의 실행 시간 상한을 확인하지 않았다.** 확인 전까지는 "사진 단위로 쪼갠다"를 기본 설계로 잡는다.
4. **디에고와 합의되지 않았다.** 4-2 의 C1~C8 은 시간 제약에서 도출한 제안이며, 4-4 순번 1(스키마 확정) 자리에서 같이 확정한다.
