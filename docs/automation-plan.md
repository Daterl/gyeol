# AI 실행 계획 — 결 GYEOL

작성: 2026-09-17. 범위는 [intent.md](intent.md)의 D1~D6이며 작업 규약은 [CLAUDE.md](../CLAUDE.md)다. 사용자는 AI의 지속적인 로컬 구현·테스트·수정을 승인했다. **사람 소유자는 리뷰 책임자이며, 로컬 초안 편집 권한과 사람 합의·merge 권한을 구분한다.** 공유 파일의 AI 편집도 허용되지만 #1 계약 및 intent C1~C8의 양쪽 사람 합의는 아직 pending이다.

## 근거와 현재 상태

실행 근거는 [intent.md](intent.md)와 GitHub [#1](https://github.com/Daterl/gyeol/issues/1), [#2](https://github.com/Daterl/gyeol/issues/2), [#7](https://github.com/Daterl/gyeol/issues/7), [#8](https://github.com/Daterl/gyeol/issues/8), [#13](https://github.com/Daterl/gyeol/issues/13), [#16](https://github.com/Daterl/gyeol/issues/16)의 교차검증 반영 내용이다. 아래 인수 예외와 책임 분담은 해당 이슈를 기준으로 한다.

- #2·#7: 초기 eval 예외, #7 curl 인수, #14로 화면 증거 이동.
- #8: #10을 기다리지 않는 수동 골든 프로필 2벌.
- #13: `position` 순으로 정렬한 **`photo_id` 배열** 비교. #13을 생략해도 D6 검사는 유지.
- #16: 출력 생성 서버도 디에고 책임. 기존 본문의 “원재에게 요청” 문구보다 추가된 범위가 우선한다.
- #1에 남은 4시간 무응답 진행 문구는 현재 사용자 지시상 **사람 합의·merge 우회 권한이 아니다**. 로컬 초안은 진행하고 합의 게이트는 남긴다.

Foundation 구현은 `7ed8d4c`에 커밋돼 있다. 커밋 존재는 사람 합의나 배포 인수 완료를 뜻하지 않는다. 이 문서는 실행 계획이며, 기존 세션과 다른 작업자의 미커밋 산출물을 보존한다.

## 실행 wave와 인수 증거

### 0. 배포 접근 확인 — #6 병렬 경로

배포를 마지막에 처음 시도하지 않도록 #6의 프로젝트·환경변수·공개 URL·smoke 확인을 foundation과 병렬로 진행한다. 권한이나 시크릿이 없으면 해당 경로만 blocked로 두고 로컬 구현은 계속한다. **Foundation은 제품 AI 및 외부 호출 0회**이며, #6의 실모델 A1 측정은 분리한다. 실호출 전 계정에서 사용 가능한 모델 ID와 접근 권한을 확인하고 시각·근거를 기록한다. 모델 이름을 추측하거나 `claude-opus-5`를 사용 가능하다고 전제하지 않는다. 키는 로그·커밋에 남기지 않는다.

A1은 배포 환경 사진 1장 측정, 함수 실행 상한, 호출 단위 결정을 남기고 최종 15장 실경로로 재검증한다. 1장 성공을 전체 성공으로 확대하지 않는다. 공개 배포·A1 증거가 없으면 #6 및 #2 전체 완료는 pending이다.

### 1. Foundation — #1 → #7 → #8

1. **#1:** 4종 스키마 v1, 15슬롯 예시, `corrected | target_only`, 간극 `caption_len_gap` 1종을 로컬 초안으로 고정한다. 변경 필드 목록과 계약 확인 결과를 남긴다. 양쪽 사람의 “합의함” 증거 전에는 계약 합의 완료로 표시하지 않는다.
2. **#7:** 4종 fixture, `present:false` 정상 경로, 15슬롯·근거·비움 후보, `GET /api/feed?mock=1`을 구현한다. **응답 계약 + curl 출력, 외부 호출 0회**가 인수 증거다. 네트워크가 없어도 같은 fixture를 반환하는지 확인한다. **화면 스크린샷은 #14**에서 남긴다.
3. **#8:** 사진 1벌과 **손으로 만든 TargetProfile 2벌**을 `eval/golden/case_01/`에 준비한다. E1·E2·E3·E6·E8의 정상 출력 및 각각 의도적으로 깨진 fixture의 실패 출력, `npm test` 결과를 남긴다. E4·E5·E7은 수동 점검으로 남긴다. #10 완료 뒤 실제 추출 결과로 교체하고 교체 전후 동일 불변식을 확인한다.

**Bootstrap 예외:** #1·#6·#7은 eval이 없던 시기의 계약 확인·배포 smoke로 인수하며 `npm run eval`을 선행 조건으로 요구하지 않는다. #8은 자신이 만든 eval을 검증하고 이후 작업부터 일반 eval 게이트를 적용한다. 배포 smoke가 미실행이면 로컬 통과와 구분해 pending으로 기록한다.

### 2. 기능 병렬 — BE #9~#13 / FE #14~#17

- **BE:** #9 사진 분석, #10 지향 프로필, #11 현재 프로필 → #12 순서 → 선택적 #13 합성. 실제 선행 입력이 준비된 작업만 진행하며, 라이브 호출이 막히면 mock/fixture와 오류 경로를 구현한다. 검증되지 않은 캐러셀 순서 근거는 사용하지 않는다.
- **FE/F3:** #14 입력·mock 화면 → #15 결과/근거 화면, 병렬 가능한 #16 타이틀·캡션 서버/프롬프트 → #17 비움 상호작용. #14는 **#7 응답 계약 인수 직후** 시작할 수 있고 #8·#2의 전체 종료를 기다리지 않는다. #7에서 넘긴 화면 스크린샷을 #14에 남긴다.
- #16은 성공·에러·타임아웃 응답 계약과 배포 curl 증거를 포함한다. 타이틀 1개 및 화면 1줄, 슬롯별 캡션/비움, 근거 허용 범위, 모델 실패 후 로딩 종료를 검증한다.
- #13을 줄이더라도 **D6은 필수**다. #12·#16·#20에서 같은 사진 + 다른 프로필 2벌의 결과를 비교한다. 각 결과를 `position`으로 정렬한 뒤 `photo_id` 배열이 다르고 캡션 결과도 다른지 확인한다. `[1,2,…,N]` 위치 배열 비교로 대체하지 않는다.

### 3. 통합 — #18 / #19 / #20

#18은 mock을 끈 실사진 경로와 실패/대체 경로를 배포 환경에서 관통한다. #19는 사전 결과 재생으로 샘플 원클릭을 구현하며 필요한 fixture·화면이 준비되면 #18의 모든 실모델 검증을 기다리지 않고 병렬 준비한다. #20은 두 경로의 증거를 모아 제출 자료와 실제 제출 완료를 구분한다.

| 목적지 | 최종 증거 |
|---|---|
| D1 | 다른 기기에서 공개 URL을 로그인 없이 연 화면 |
| D2 | 샘플 버튼 1회로 30초 이내 결과 도달, 기기·측정 시간 |
| D3 | 3장/20장 경계와 21장 거부, 대표 15장의 중복·누락 없는 순서 및 슬롯별 근거 |
| D4 | 타이틀 1개 반환과 화면 1줄 표시 |
| D5 | 기본 결과의 채움·비움 각각 ≥1, 비움 이유·채우기 동작, 사용자 편집 보존 |
| D6 | 동일 사진·서로 다른 프로필의 JSON 및 화면 2벌, 정렬된 photo_id 순서와 캡션 차이 |

캡션은 사진에 없는 장소·인물·시간을 말하지 않는지 사람이 전수 대조한다. 팀 밖 2명의 비움 화면 반응, A2 캐러셀 근거 확인, 참가 신청·제출 담당과 접수 증거는 별도 사람 확인 항목으로 남긴다. 로컬 fixture의 구조 검사 통과를 개인화 품질이나 배포 성공으로 취급하지 않는다.

### 4. 크기별 리뷰 · Draft PR → 사람 merge → 배포 검증

두 모델 리뷰는 [CLAUDE 3절](../CLAUDE.md)의 **L 필수 · M 권장 · S 생략**을 따른다. 리뷰를 실행할 때는 서로 다른 모델 2개에 같은 diff를 전달하고 모델 ID·실행 시각·기준 commit과 diff 식별자·원문 응답·지적별 반영 여부를 남긴다. L의 수정으로 diff가 바뀌면 최종 diff를 다시 두 모델에 전달한다. **지적 0건도 유효한 리뷰**이며 미실행·호출 실패를 0건으로 바꾸지 않는다. 필수 리뷰 모델을 확보하지 못하면 L의 리뷰 게이트를 pending으로 두되, M의 권장 리뷰를 필수 게이트로 올리지 않는다.

**필수 리뷰나 검증이 pending이어도 Draft PR을 열 수 있다.** 현재 증거와 미완료 게이트를 본문에 표시하고, 부분 구현·인수 대기는 **`Refs #N`**으로 연결한다. 이슈 전체 인수조건을 충족한 경우에만 `Closes #N`을 사용해 조기 자동 종료를 막는다. Ready for review는 크기별 필수 사전 게이트(필요한 테스트·요구사항 검증·L의 두 모델 리뷰·계약 합의)가 통과한 뒤로 제한한다.

Ready 이후 해당 사람 소유자의 리뷰와 상대 사람 리뷰어의 merge를 거친다. 배포 URL에서 기능을 다시 실행해 증거를 남기며 초기 #6 smoke로 최종 배포 확인을 대신하지 않는다. **시간 초과 자동 승인·자동 merge·main 직푸시는 하지 않는다.** 커밋 권한이 주어진 실행에서는 CLAUDE 5-2의 Lore 형식과 실제 작성자 신원을 사용한다.

## 실패 처리와 중단 조건

동일 실패의 자동 수정은 **최대 3회**다. 각 회차의 가설·수정·재검사 결과를 남기며, 해결되지 않으면 그 작업을 **blocked**로 표시하고 필요한 사람 결정 또는 외부 조건을 전달한다. **독립 작업은 계속한다.** 새 증거 없이 횟수를 초기화하거나 무한 재시도하지 않는다. 키·모델·배포 접근이 없으면 실패할 실호출을 반복하지 않는다.

AI 실행을 사람 작업시간의 일정 배수로 환산하거나 속도 향상 비율을 약속하지 않는다. 실제 진척은 산출물·검증 증거·남은 게이트로 기록한다.

종료 조건은 해당 작업의 크기·범위에 적용되는 필수 검증, L의 최종 동일 diff 두 모델 리뷰, 필요한 사람 합의·merge 및 배포 확인의 증거가 존재하는 것이다. 문서만 바뀌어 제품 실행에 영향이 없으면 배포 기능 확인은 해당없음으로 기록한다. 로컬 구현만 끝났다면 **“로컬 완료, 외부 게이트 pending”**으로 보고한다. 사람 합의, 모델 접근, 실배포/A1, 리뷰 실행, merge 및 제출 완료는 각각 실제 증거로 판정한다.
