01 / RESEARCH

‘사진 여러 장’은 하나의 기능이 아니다.

캐러셀 한 게시물, 여러 게시물의 프로필 그리드, 이어지는 스토리는 서로 다른 편집 단위를 가진다. 기존 3–20장 정렬만으로는 이 차이를 표현하기 어렵다.

한 장도 완성된 게시물

사진 한 장에도 캡션·위치·음악·대체 텍스트가 있다. 정렬할 사진이 없다고 GYEOL을 시작하지 못할 이유는 없다.

공식 사진 게시 도움말 ↗

캐러셀은 게시물 한 개

최대 20개 미디어가 한 게시물이다. iPhone 공식 안내에는 공통 캡션과 항목별 복수 캡션이 있어, 둘의 적용 단위를 구분해야 한다.

스토리는 장면과 반응

24시간의 기록에 위치·음악·질문·링크·투표가 붙는다. 정적 이미지 제안과 앱에서 작동하는 스티커를 구분해야 한다.

현재 URL 검증은 계정 경로만 받는다. /p/ 게시물 링크와 1·2장 지원은 문구 수정만으로 되지 않으며 입력·서버 검증·응답 계약을 함께 바꿔야 한다. 프로필 그리드의 네이티브 재배열 지원은 계정별 직접 확인이 남아 있다.

02 / PLANNING

내 게시물 링크로, 내 방식 알려주기.

“내 기존 게시물 사진으로 알려주기”를 “내 기존 게시물로 알려주기”로 넓힌다. 링크를 우선 제안하되 사진만으로 바로 시작하는 한 화면 원칙은 유지한다.

선택 입력 · 화면 설계 예시

내가 쓴 게시물 링크를 넣어 주세요.

https://www.instagram.com/p/게시물코드/

처음에는 1–5개 링크부터. 가져온 사진과 원문 캡션을 확인하고, 반영할 기록만 선택한다.

1–5개는 초기 제품 제안이다. 실제 수집 기능은 미구현이며 이 문서에서 URL을 전송하지 않는다.

01 / 링크 넣기

게시물 단위로

계정 전체 대신 내가 고른 기록을 참고한다. 수집 대상·제공자·비용을 먼저 안내한다.

02 / 가져온 내용 확인

원문과 출처

사진 순서·캡션·수집 시점과 누락 필드를 확인한다. 링크만으로 소유권을 인증하지 않는다.

03 / 필요한 것 보완

실패해도 계속

비공개·삭제·접근 제한이면 사진과 캡션을 직접 넣는다. 성공한 항목과 편집은 남긴다.

04 / 내 결과에 반영

아는 만큼만

사진 특징과 문체의 근거를 보여준다. 한 게시물로 전체 계정의 취향을 단정하지 않는다.

공개 링크 수집과 계정 연결은 다른 기능이다.Apify는 게시물 URL 입력을 문서화하고 있지만 비공개 계정 수집을 보장하지 않는다. 공식 Instagram Login API는 비즈니스·크리에이터 대상이다. 일반 개인 계정까지 항상 읽는다고 약속하지 않는다. 출처 확인 ↓

각 항목을 펼쳐 제안 경험을 확인할 수 있다. 기존 샘플 이미지를 사용한 기획 예시다.

한 장 사진 1장 · 말의 양을 고르기

한 장으로 충분한 날.

사진과 선택 맥락을 바탕으로 캡션·비움·대체 텍스트를 제안한다. 순서 근거나 억지 서사 구조를 만들지 않는다.

장소·상황·곡 메모는 필요할 때만 더한다. 사용자의 말을 보존하고 비움을 강제하지 않는다.

기존 ‘최소 한 슬롯 비움’ 시연 기준을 단일 사진에 그대로 적용하지 않는다.

캐러셀 사진 2–20장 · 커버와 내부 흐름

하나의 게시물 안에서 이어지는 장면.

커버·내부 순서·공통 크롭을 미리 본다. 공통 캡션과 항목별 캡션 초안을 구분하고 사진별 근거를 보여준다.

위치는 게시물에, 사람 태그는 해당 사진에 연결한다. 캡션을 비워도 사진이 삭제되지는 않는다.

대상 앱의 복수 캡션 지원을 확인한다. 미지원 시 사용자 선택 없이 합치거나 버리지 않는다.

프로필 그리드 게시물 묶음 · 계정 화면의 조합

사진 순서와 게시물 순서를 나누기.

기존 게시물 옆에 새 게시물을 놓아 색·밀도·장면 반복을 살핀다. 게시물 단위 이동과 캐러셀 내부 이동을 분리한다.

고정 게시물과 실제 배열은 사용자가 확인한다. 수집 시간순이 실제 프로필 순서와 같다고 가정하지 않는다.

배치 시뮬레이션이며 Instagram 계정을 직접 재배열하거나 홈 피드 노출 순서를 바꾸지 않는다.

스토리 사진 기반 프레임 · 짧은 말과 상호작용

짧게 이어지고, 답을 받을 수 있게.

프레임 순서·텍스트 여백·위치/음악/질문/링크 스티커 메모를 준비한다. 초기 세션은 사진 1–20장 제안이며 플랫폼 제한을 뜻하지 않는다.

최종 링크·투표·음악은 Instagram에서 적용한다. 저장된 스토리 사진과 설명으로도 시작할 수 있게 한다.

24시간 만료 링크를 영구 기록처럼 취급하지 않는다. 동영상 편집·음원 첨부·자동 게시 기능은 포함하지 않는다.

사진이 말해 주지 않는 것은, 사용자에게서.

근거가 보이는 결과

사진 관찰 · 게시물 메타데이터 · 사용자 설명 · 모델 제안을 구분한다. 미수집은 ‘없음’과 다르다. 원문과 수정본을 보존하고 참고 기록을 제외할 수 있게 한다.

선택이 남는 편집

형태를 바꾸거나 다시 생성해도 원본·초안·비움 상태를 유지한다. 작업 타이틀을 Instagram 고유 필드처럼 표시하지 않는다. 음악·스티커는 네이티브 앱으로 인계한다.

03 / UMBRELLA

한 번에 넓히되, 순서대로 완성한다.

이번에는 설명식 엄브렐라 하나에 전체 방향을 담는다. 아래 순서는 의존성을 설명하는 계획이며, 아직 서브태스크를 생성하지 않는다.

  1. 발행 단위와 경계 계약 정리 공동

    사진과 게시물, 공통/항목별 캡션, 1·2장·비움 기준을 먼저 정한다. 기존 photo_id·근거·편집 store를 재사용하고 구버전 초안을 보존한다.

  2. 한 장·캐러셀 + 본인 게시물 링크 diego + enzo

    입력부터 내보내기까지 연결한다. 링크 수집의 공개/비공개/삭제/부분 성공을 실증하고, 수집이 막혀도 사진·원문 캡션 수동 경로로 진행한다.

  3. 프로필 그리드와 게시 맥락 diego 중심

    게시물 묶음, 장소·상황·노래 메모·태그별 편집을 결과와 연결한다. 기본 맥락 입력은 B에도 포함한다.

  4. 사진 기반 스토리 공동

    프레임·오버레이·스티커 인계부터 검증한다. 정적 제안이 실제 링크·투표·음원처럼 보이지 않도록 한다.

범위 설명 초안

내 기록을 이해하고, 발행 형태에 맞는 구성을 준비하는 GYEOL

기존 사진 순서·캡션·비움 경험을 기반으로 본인 게시물 링크와 선택 맥락을 받아들인다. 한 장·캐러셀·프로필 그리드·스토리를 서로 다른 단위로 다루고, 원문과 사용자 편집을 보존한다.

완료는 화면 추가가 아니라 실제 입력 → 근거 확인 → 편집 → 형태별 내보내기의 연결로 판단한다. 공개 링크 실수집, 대상 앱의 기능 차이, 개인화 품질 검증은 별도 증거가 필요하다.

완료를 확인할 장면

  • 1장·2장·20장이 끝까지 이어지고 21장은 안내한다.
  • 실패한 링크가 있어도 성공한 기록과 편집은 남는다.
  • 캐러셀 한 개가 그리드 한 칸으로 유지된다.
  • 근거 없는 장소·시간·관계·곡을 만들지 않는다.
  • 형태 전환 후에도 사용자의 초안이 남는다.

구현 전 남은 확인

  • 제공자 필드·시간·비용·보관/삭제 정책 실증
  • 실제 앱의 캡션·음악·태그·스토리 인계 확인
  • 공유 계약 변경과 기존 D3–D5 기준 조정
  • 본인 게시물로 개인화 품질 검증

제품 코드·자동 게시·Production은 이번 문서 작업에서 변경하지 않는다.
