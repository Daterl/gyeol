# ADR-0008: 공개 프로필 연결부터 큐레이션 확정·공유까지

- 날짜: 2026-09-18
- 상태: 제품 계약 확정 — 구현·외부 연동·실기기 검증은 별도
- 결정자 / 화면·출력·공유 담당: **diego.yoon** (`@jangwonyoon`)
- 협업자 / 입력 이해 담당: **enzo.cho** (`@onejaejae`)
- 관련: [ADR-0006](0006-apify-public-instagram.md), [ADR-0007](0007-mobile-first-experience.md)

## 배경

기존 제품은 사진만으로 시작하는 선택 경로와 3~20장 입력을 허용했다. 후속 그릴링에서 공개 Instagram 프로필 연결을 첫 필수 단계로 두고, 3~15장 사진을 큐레이션한 뒤 프리뷰에서 편집·확정해 공유하는 흐름으로 제품 계약을 변경했다. 별도 DB가 없는 현재 구조에서 작성 중 상태와 다른 사람이 여는 공유 상태도 분리해야 한다.

## 제품 흐름

`공개 프로필 연결 → 사진 3~15장 → 선택 프롬프트 → 큐레이션 프리뷰·편집·확정 → 공유 링크`

1. 사용자는 공개 Instagram 프로필 URL을 반드시 연결한다. Apify `apify/instagram-scraper`로 공개 여부와 공개 프로필·게시물을 확인하며, 비공개 계정은 진행을 막고 다른 공개 프로필 연결을 안내한다.
2. 이 연결은 OAuth나 소유권 인증이 아니다. 다른 사람의 공개 프로필도 입력할 수 있으므로 화면에는 `공개 프로필 연결`이라고 쓰고 본인 소유 여부를 확인하지 않았음을 알린다.
3. 프로필은 연결 직후 한 번 수집한다. 정규화한 사용자명의 해시를 경로로 쓰는 Private Blob 캐시에 스냅샷과 만료 시각을 두어 다른 브라우저와 URL 표기 차이에도 24시간 제공자 재호출 제한을 적용한다. 조건부 생성 reservation으로 동시 요청 하나만 제공자를 호출하고, 만료된 스냅샷·실패 기록·reservation은 일일 정리에서 삭제한다. 24시간이 지난 뒤에는 사용자가 요청할 때만 새로고침하며 자동 반복 호출하지 않는다. 실패를 비공개로 단정하지 않는 기준은 ADR-0006을 따른다.
4. 사용자는 사진 3~15장을 올린다. 공유할 사진은 브라우저에서 긴 변 1440px WebP로 만들며 이 과정에서 EXIF·GPS를 제거한다. 원본은 분석 요청 뒤 보관하지 않는다.
5. 프롬프트는 선택이다. 입력하면 사진 선택·순서·캡션 초안에 함께 반영하고, 비워 두면 연결한 공개 프로필의 수집 가능한 스타일 근거를 사용한다.
6. 큐레이션은 필수다. 기본은 모든 사진을 포함하고 AI는 순서·제외 후보와 이유·캡션 초안을 제안할 수 있다. 사용자는 **큐레이션 확정 전 프리뷰**에서 순서를 바꾸고, 사진을 제외·복원하고, 캡션을 편집하거나 비울 수 있다. 확정은 이 편집 결과의 공유용 스냅샷을 만든다는 뜻이다.

## 모바일 우선 화면

- 편집 흐름은 최대 480px 모바일 캔버스를 기준으로 하고 큰 화면에서는 가운데 배치한다. 공유 피드는 데스크톱에서 최대 935px까지 넓힌다.
- Instagram의 정보 구조를 참고해 프로필 헤더, 3열 정사각형 그리드, 사진 상세 화면을 사용한다. 상세 사진은 원본 비율을 유지하고 사용자는 그리드 썸네일의 중심 위치를 조정할 수 있다.
- 390×844 공개 프로필 실측에서 흰 배경 `#FFFFFF`, 검정 본문, 구분선 `#DBDBDB`/`#DBDFE4`, 보조 글자 `#8E8E8E`, 링크 `#00376B`와 `상단 바 → 프로필·소개·링크 → 가로 하이라이트 → 지표 → 탭 → 3열 그리드` 위계를 확인했다. 제품은 이 중립 팔레트와 프로필·소개·링크·그리드의 여백 위계를 참고한다. 실측 화면의 약 3:4 타일 대신 확정한 1:1 썸네일을 유지한다.
- 좋아요·댓글·팔로워 수는 넣지 않는다. Instagram 로고·고유 아이콘·고유 그라데이션도 복제하지 않는다. GYEOL 캐릭터와 포인트 색으로 제품을 구분한다.
- 터치 크기, 키보드 조작, safe area, reduced motion과 실기기 확인은 ADR-0007과 ADR-0003을 따른다.

## 초안과 공유 저장

1. 작성 중 프로필 요약, 사진 ID·순서, 프롬프트와 프리뷰 편집 메타데이터는 브라우저 `localStorage`에 보존한다. 15장 이미지 바이트는 용량 한도를 넘을 수 있으므로 정규화한 WebP Blob만 브라우저 기본 `IndexedDB`에 둔다. 둘 다 초안 복구용이며 서버 DB나 다른 사람이 여는 공유 데이터가 아니다.
2. 확정한 1440px WebP 사진과 큐레이션 JSON은 **Private Vercel Blob**에 버전별 불변 객체로 저장한다. 15장을 한 Function body로 보내지 않는다. 서버는 share ID·version·정렬된 사진 ID/해시·10분 이내 만료를 서명한 큐레이션 영수증에만 업로드 세션을 발급한다. 영수증 해시의 durable marker를 조건부 생성해 최초 요청에는 세션을 만들고 재요청에는 같은 세션을 반환하며, 다른 세션의 반복 발급을 막는다. 세션은 share/version prefix·사진 ID·최대 15개·`image/webp`·파일별/총 바이트 상한에 묶는다. 발급 route에도 배포 환경의 요청 제한을 둔다. 모든 예상 객체의 크기·타입·해시를 확인한 뒤에만 manifest를 게시한다.
3. 같은 공유 주소는 Private Blob manifest가 가리키는 가장 최근 확정 스냅샷을 보여준다. manifest에는 상태, current version, `photo_id → pathname·해시·타입·크기` 객체 목록, 관리 키 해시와 프로필 표시 선택·출처·시각을 둔다. 선택하지 않은 프로필 PII와 관리 키 원문은 저장하지 않는다. manifest 읽기는 캐시를 우회하고 공유·이미지 route는 `no-store`로 응답한다. 이미지 route는 `shareId + photoId`만 입력받아 active manifest의 current version에 등록된 pathname을 서버가 선택하며, 클라이언트 pathname·다른 share·이전 version·tombstone 객체를 거부한다. 재확정·관리 키 회전·비활성화는 현재 ETag의 `ifMatch` 조건부 쓰기를 사용하며 충돌하면 덮어쓰지 않고 다시 불러오게 한다.
4. 활성 링크는 자동 만료하지 않는다. 새 manifest가 게시되면 이전 버전 객체를 삭제한다. 중단·실패한 업로드는 임시 prefix와 세션 만료 시각을 기록하고 일일 정리 작업에서 24시간 뒤 삭제한다. 비활성화는 먼저 manifest를 일관 읽기·조건부 쓰기로 tombstone으로 바꾼 뒤 연결된 모든 이미지·JSON을 삭제한다. tombstone에는 사진·캡션·프로필 PII를 남기지 않는다.
5. OAuth와 계정 소유권 인증이 없으므로 공유 관리 권한은 별도 관리 키로 확인한다. share ID는 CSPRNG 128bit 이상, 관리 키는 256bit 이상으로 생성한다. 관리 키는 생성 시 사용자에게 보여 주고 `localStorage`에 보존하며 manifest에는 SHA-256 해시만 저장한다. 관리 route는 timing-safe 비교와 요청 제한을 적용하고, 회전은 조건부 manifest 쓰기가 성공한 즉시 이전 키를 무효화한다. 다른 기기에서는 키를 직접 입력하고, 잃어버린 키는 복구하지 않는다.
6. 프리뷰에서 프로필 사진·표시 이름·사용자명을 공유할지 기본 꺼짐 상태에서 명시적으로 선택한다. 이는 공유를 만드는 사용자의 포함 선택이며 프로필 주체의 동의나 소유권 증명이 아님을 알린다. manifest에는 선택값, 프로필 스냅샷 출처와 수집 시각을 저장한다. 선택하지 않으면 공유 페이지는 GYEOL 일반 헤더를 쓰고 프로필 PII를 저장·표시하지 않는다. 소유권 인증 표식, 팔로워 수, 좋아요, 댓글은 어느 경로에도 표시하지 않는다.

## 대체 관계와 확인 기준

- 이 ADR은 ADR-0001의 사진만으로 시작, 선택 프로필, 3~20장 결정을 대체한다. 기술 스택, 공개 자료만 수집하는 제한, 모바일 접근성 기준은 각각 ADR-0002·0006·0007을 유지한다.
- 공개 프로필을 연결하지 않았거나 비공개로 확인되면 사진 단계로 진행할 수 없다. 연결은 인증으로 표현되지 않는다.
- 2장·16장은 거절하고 3장·15장은 프리뷰까지 진행한다. 프롬프트를 비워도 큐레이션이 생성된다.
- 프리뷰 편집은 확정 전에 가능하며, 재확정하기 전 기존 공유 주소에는 마지막 확정본이 유지된다.
- 새 브라우저에서 공유 주소만으로 확정본을 볼 수 있고, 관리 키 없이는 수정·비활성화할 수 없다.
- 비활성화 직후 공유·이미지 route가 tombstone을 확인해 내용을 반환하지 않으며 연결된 미디어가 삭제된다. 프로필 표시 동의 전에는 프로필 PII가 공유 manifest에 들어가지 않는다.
- 이미지 route는 manifest 소속이 아닌 pathname과 과거 version을 읽지 못한다. 같은 큐레이션 영수증은 한 업로드 세션에만 대응하며 관리 키 회전 뒤 이전 키는 즉시 거부된다.
- 이 문서 변경은 Apify 호출, Blob 생성, UI 구현이나 Production 배포 완료를 의미하지 않는다.

## 기술 근거

- [Vercel Blob](https://vercel.com/docs/vercel-blob): private/public 접근, 불변 객체 권장, ETag 조건부 쓰기와 overwrite 캐시 경계
- [Private Blob consistent reads](https://vercel.com/changelog/vercel-blob-now-supports-consistent-reads-on-private-storage): 최신 manifest를 위한 cache bypass
- [Vercel Blob client uploads](https://vercel.com/docs/vercel-blob/client-upload): content type·size·만료를 제한하는 업로드 토큰
- [Vercel Functions limits](https://vercel.com/docs/functions/limitations): 한 요청에 15장 전체를 싣지 않는 근거
