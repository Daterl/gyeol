# ADR-0007: 앱 전체를 모바일 우선으로 설계

- 날짜: 2026-09-18
- 상태: 제품 방향 확정 — diego.yoon 결정. 화면별 적용·실기기 검증은 별도
- 결정자: **diego.yoon** (`@jangwonyoon`) / 협업: **enzo.cho** (`@onejaejae`)
- 관련: [확장 엄브렐라 #65](https://github.com/Daterl/gyeol/issues/65), [ADR-0001](0001-single-screen-photo-only-entry.md), [ADR-0002](0002-react-stack-and-ai-session-graph.md)

## 배경

사용자가 앱 자체를 모바일 우선으로 진행하도록 요청했다. 사진 선택, 게시물 링크 붙여넣기, 편집과 Instagram으로의 인계까지 모바일을 기준으로 설계해야 한다. 기획서가 작은 화면에서 보이는 것만으로 앱의 모바일 경험이 완성된 것은 아니다.

## 결정

1. **모바일 웹이 기본 경험**이다. 기존 Next.js·React·TypeScript·Zustand·Tailwind CSS·shadcn/ui·tv 스택을 유지한다. 이 결정으로 네이티브 앱·PWA·새 UI 라이브러리를 추가하지 않는다.
2. 입력 → 생성 대기/오류 → 결과 확인 → 순서·캡션 편집 → 내보내기의 전체 흐름을 작은 화면과 터치 기준으로 먼저 설계한다. 한 화면·선택 아이덴티티 원칙을 유지하고 보조 정보는 필요할 때 펼친다.
3. 기본은 한 열과 세로 흐름이다. 데스크톱은 추가 여백·다중 열·동시 미리보기로 확장하되 핵심 기능은 양쪽에서 동일하게 사용할 수 있어야 한다. 화면 전체의 가로 넘침을 막고 캐러셀 등 의도된 가로 이동만 해당 영역에 한정한다.
4. 주요 터치 대상은 44×44 CSS px 이상을 기준으로 삼는다. hover나 드래그만으로 동작하는 기능을 만들지 않고 순서 이동 버튼·키보드 조작·명확한 레이블을 제공한다.
5. 모바일 키보드가 올라와도 입력 중인 캡션과 주요 조작을 가리지 않는다. 하단 고정 영역을 쓰면 safe area와 콘텐츠 여백을 확보한다. 사진 선택·재시도·형태 전환 중 원본과 사용자 초안을 보존한다.
6. 사진 미리보기는 화면 크기에 맞추고 불필요한 동시 업로드·큰 이미지 렌더링을 피한다. 로딩·실패·취소 상태를 모바일에서 확인할 수 있어야 한다. 근거 없는 속도 수치나 실기기 검증 완료를 주장하지 않는다.

## 확인 기준과 적용 순서

- 구현 검토는 390px을 기준으로 시작하고 360px·430px에서 잘림·가로 넘침·조작 누락을 확인한다. 태블릿·데스크톱도 기능과 읽기 순서를 확인한다. 이 폭은 QA 기준이며 특정 기기만 지원한다는 뜻이 아니다.
- 모바일 사진 선택, 링크 붙여넣기, 키보드를 연 캡션 수정, 순서 변경, 취소/재시도, 내보내기를 실제 모바일 브라우저에서 확인한다. 데스크톱의 좁은 뷰포트 검사는 실기기 인수를 대신하지 않는다.
- 기존 입력·편집·내보내기의 모바일 경로를 먼저 점검하고 #65의 한 장·캐러셀·그리드·스토리 확장에도 같은 원칙을 적용한다. 현재 기획서 화면 검증을 앱 전체 적용 완료로 표시하지 않는다.
- diego.yoon은 화면·상태·접근성과 모바일 QA, enzo.cho는 입력 이해와 요청/응답·실패 처리에 협업한다. 이번 변경은 문서이며 제품 레이아웃 구현 완료를 뜻하지 않는다.
