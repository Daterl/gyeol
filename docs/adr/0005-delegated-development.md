# ADR-0005: 검증에 근거한 develop 셀프 머지 위임

- 날짜: 2026-09-17
- 결정자: **diego.yoon** / 협업: **enzo.cho**
- 상태: 사용자 명시 승인. 이전 사람-only develop merge 지침을 대체한다.

## 승인 범위

사용자는 추천 1A/2A/3A/4A 전부를 승인하고 “다 머지한다음 에비던스를 확인하면서 셀프머지로 작업해 계속 돌려”라고 지시했다.

- diego 담당 기능·디자인 #24~27, #14~19, #34~36을 가능한 범위까지 진행한다. #37 Motion은 핵심 기능·정적 디자인 검증 뒤 진행할 수 있다.
- 기존 제품 범위 안의 요청·응답·오류·편집 기술 계약을 AI가 결정·기록한다. enzo 작업과 충돌하면 해당 파일 범위만 보류하고 독립 작업을 계속한다.
- 각 변경의 테스트·타입·린트·빌드·필요한 UI 검증 증거를 남기고 중요한 미해결 결함이 없을 때 **develop**에 셀프 머지한다. 문서만 바뀌는 경우 관련 없는 앱 검사는 해당없음으로 적는다.
- enzo 작업은 기존 산출물을 검토·통합하며 동시 작업 파일을 덮어쓰지 않는다.
- **main 릴리스·Production 배포, 유료 모델 호출은 위임하지 않았다.** 모델 경로는 fake-provider/계약/실패 검증과 실호출 검증을 구분한다.
- 이슈 종료는 merge 자체가 아니라 전체 DoD 증거로 판단한다. 외부 실측·실기기·사람 대상 검증이 남으면 pending을 유지한다.

이는 무응답을 승인으로 취급하는 예외가 아니라 실제 사용자 위임이다. 제품 범위 확대·외부 비용·삭제·새 권한 부여를 자동 승인으로 확대하지 않는다.
