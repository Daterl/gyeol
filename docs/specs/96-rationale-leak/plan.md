# 어떤 순서로 — 실측을 먼저 고정한다

고칠 곳은 한 줄이다. 어려운 것은 "고쳐졌다"를 1/10 빈도에서 증명하는 쪽이라,
**수정 전 실측을 먼저 확보하고** 그 다음에 코드를 만진다.

| # | 무엇을 | 파일 | 무엇으로 확인 |
|---|---|---|---|
| 1 | 탐지기 + 재현 하네스 | `docs/specs/96-rationale-leak/probe.mjs` | `build` 로 만든 feed 가 `validateFeedResponse` 를 통과한다 |
| 2 | 실사진 11장 분석 → feed 1개 고정 | (1)의 `build` 서브커맨드 | 같은 feed 를 전/후에 재사용해야 통제된 비교가 된다. 캐시 JSON 으로 디스크에 남긴다 |
| 3 | **수정 전** 실모델 10회 | (1)의 `run` | 금지 패턴 히트 ≥ 1건 — 재현 못 하면 이 이슈의 증명이 성립하지 않는다 |
| 4 | 화이트리스트 적용 | `lib/output-generation.js` | `npm test` 통과 |
| 5 | 회귀 테스트 | `test/generate.test.js` | 슬롯을 통째로 되돌리면 실패하는지 직접 확인 |
| 6 | **수정 후** 실모델 10회 | (1)의 `run` | 히트 0건 |
| 7 | 프롬프트 규정 (이중 방어) | `prompts/shared/style_guard.md` | 6번이 이미 0건이어도 넣는다. 4번은 재료를 없애고 7번은 어휘를 막는다 |
| 8 | 전체 검증 | — | `npm test` · `npm run eval` |
| 9 | 기록 | `docs/specs/96-rationale-leak/report.md` | 회차별 타이틀 전부를 표로 남긴다 |

## 3번에서 재현이 안 되면

10회로 안 나오면 20회까지 늘린다. 그래도 0건이면 **고쳤다고 말하지 않는다.**
"입력에 rationale 이 실려 있었다" 는 구조 사실(회귀 테스트)만 근거로 남기고,
"유출이 사라졌다" 는 주장은 하지 않은 채 이슈에 그대로 적는다.

## 비용

- 사진 분석: 11장 × 1회 = 11 vision 호출 (`claude-opus-5`). 2번에서 한 번만. 캐시 재사용.
- 출력 생성: 10회 × 2패스 = 20 호출 (`claude-haiku-4-5`, 17~21초/회) ≈ 7분.
