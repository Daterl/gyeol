# #97 제외 후보 품질 — 유사성·묶음 조화·프로필 근거

`docs/intent.md` 중 향하는 줄: **"이 사진은 빼는 게 낫습니다" 를 근거와 함께 말한다** (#88 의 연장, P2·P3).

## 1. 어디까지 하는가 — DoD 첫 항목의 결정

| # | 후보 | 결정 | 근거 (측정) |
|---|---|---|---|
| **A** | 비슷한 사진 | **한다** | 기존 관측값으로는 불가능했으나, 분석기가 이미 디코드하는 JPEG DC 밝기 격자로 실사진 40,726쌍에서 오탐 0건을 얻었다 (report.md 2·3절) |
| **B** | 묶음 내 조화 | **하지 않는다** | A 와 같은 값에서 반대 방향(이질성)을 읽는 것인데, 그 값이 유사도조차 가르지 못한다는 것을 먼저 확인했다. "조화 없음" 을 관측값으로 정의할 근거가 없다 |
| **C** | 프로필과의 거리 | **하지 않는다** | 실경로의 지향축은 `completeness.visual = 0` 이다(`lib/order.js` 주석, `eval/golden/case_01/target_detail.json`). 프로필이 시각축을 말하지 않는데 거리를 재면 없는 지향을 지어내는 것이다 — 이슈가 "프로필 축이 비어 있으면 판단하지 않는다" 고 적은 그대로다 |
| **D** | 느낌 없는 사진 | **하지 않는다** | "별로" 는 취향이라 P2·S4 와 충돌한다. 대안으로 제시된 관측 가능한 경로(`dark`)도 실사진 291장에서 **0장** 발화한다(`DARK_BRIGHTNESS` 0.25 vs 밝기 하위 10% 0.383). 만들어도 동작하지 않는 코드다 |

## 2. 입력과 출력

- 입력: `PhotoAnalysis[]` 3~20장. 각 사진은 선택 필드 `structure_signature`(number[64])를 가질 수 있다.
- 출력: 기존 `OrderedFeed.slots[].omit_suggestion` 과 `omit_summary`. **새 필드를 만들지 않는다.**

## 3. 완료 조건 — 관측 가능한 문장

1. 두 사진의 `structure_signature` 거리가 `SIMILAR_DISTANCE`(0.40) 미만이면 **나중에 들어온 사진**에 `recommended: true` 가 붙고, 먼저 들어온 사진은 붙지 않는다. 거리는 `signatureDistance` 가 **소수 4자리로 반올림한 값** 기준으로 비교한다.
1-1. 비교 원본은 **남기기로 한(retained) 사진뿐**이다. 이미 빼기를 권한 사진(유사·동일 바이트 중복 모두)은 다음 사진의 비교 원본이 되지 않는다 — A←B←C 연쇄에서 "B를 빼라" 와 "B를 남기고 C를 빼라" 를 동시에 말하면 권고를 따랐을 때 C의 근거가 사라진다.
1-2. 서명은 **화면에 보이는 방향** 으로 잰다. JPEG 은 EXIF Orientation 1~8 을 적용하고, PNG/WebP 썸네일은 auto-orient 후 측정한다. 방향 메타데이터만 다른 두 파일은 같은 배치이고, 돌려서 다르게 보이는 사진은 기준 밖이어야 한다.
2. 그 판정을 가른 **구조 거리와 기준값 0.40 이 사용자가 읽는 `reason` 과 `evidence[].note` 에 숫자로 함께** 나타난다.
3. `evidence` 는 두 개이며 모두 `kind: "uploaded_photo"` 이고 `ref` 가 **이번 입력 사진 ID** 로 해소된다 (E10).
4. 두 사진 중 하나라도 서명이 없으면 **권고하지 않는다.** 동일 바이트 중복(#88)이 이미 잡힌 사진에는 유사 이유를 덧붙이지 않는다.
5. 공개 `/api/feed` 는 `analysis_receipt` 가 그 서명을 인증한 경우에만 서명을 관측값으로 쓰고, 그 외에는 **필드를 지운다.**
5-1. v1 영수증(구 서버 발급)은 **바이트 중복까지만** 신뢰한다. 기존 `duplicate_of` 권고는 그대로 유지되고, 서명은 항상 지워져 유사 권고가 나오지 않는다 (fail closed). v1 영수증을 통째로 거절해 기존 중복 권고를 조용히 없애지 않는다.
6. 계약 검증은 입력 `PhotoAnalysis` 로 **재계산해 대조**한다. 위조한 판정·거리·근거·합계는 거부된다.
6-1. 배포 이전 브라우저 번들(규칙 1: 동일 바이트 중복만)이 같은 서버에 붙어도 **정상 응답을 버리지 않는다.**
   요청 헤더 `X-Gyeol-Omit-Rules` 로 규칙 번호를 협상해 서버는 호출자가 재계산할 수 있는 범위까지만 답하고,
   헤더가 없으면 규칙 1 로 답한다. 검증은 지원 규칙 중 하나와 정확히 맞으면 통과시켜 롤백 방향도 연다.
   위조(없는 권고를 지어내는 방향)는 어느 규칙과도 맞지 않으므로 여전히 거부된다.
7. `입력 N장 = 출력 N칸`(E1)이 유지되고 모든 큐레이션 슬롯은 `included: true` 다 — **자동 제외 없음.**
8. 실사진으로 **발화율을 측정**하고 보고서에 적는다. 0% 도 100% 도 아닌 실제 수치여야 한다.
8-1. 임계값을 **고른 표본과 확인한 표본을 분리**한다. 게시물을 이름 해시로 두 겹으로 갈라 dev 쪽에서만
   선정 절차를 다시 돌리고, 그 임계값을 한 번도 보지 않은 holdout 쌍에 적용해 **다른 게시물 오탐 수**를
   보고한다. 두 겹을 모두 돌려 모든 게시물이 한 번씩 holdout 이 된다.
9. 미관측 필드(`composition`·`scale`·`has_face`·`subjects`·`text_in_image`·`describable_facts`·`dark`·`blurry`) 변조에서 **권고 변경 0건.**
10. `npm test` / `eval` / `check` / `lint` / `typecheck` / `test:ui` 통과.

## 4. 하지 않는 것

- 사진을 자동으로 빼지 않는다. 권고만 한다 (P1).
- 권고를 억지로 만들지 않는다. 0건도 정상이며 그 사실을 `omit_summary` 에 적는다 (P3).
- 모델을 호출하지 않는다. 새 의존성을 더하지 않는다.
- 화면 구현은 범위 밖이다 (디에고 소관). 서버가 내는 데이터까지다.
