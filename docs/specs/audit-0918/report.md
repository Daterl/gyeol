## 5. 제품 드리프트와 다섯 번째 함정

### 가장 큰 드리프트는 추가 기능보다 핵심 결과의 부재

공개 화면은 “올릴 순서를 고르고, 필요한 말만 붙인다”고 말하지만, 현재 분석은 키 부재로 heuristic이고 main은 그 입력을 원순서로 보존한다. 생성은 503이다. 사전 작성 샘플 편집이 실제 큐레이션의 대체물이 된 상태다. UI의 “취향에 맞춰 다시 정렬한 결과는 아니에요” 고지는 정직하지만 핵심 기능의 부재를 해소하지 않는다.

원기획 V3는 **동일한 지향·동일 사진에서 CurrentProfile만 달리해** 보정축의 기여를 검증한다. 축소 intent S3는 서로 다른 프로필 두 벌의 photo_id 차이다. 후자를 통과해도 전자의 “사람마다 달라진다/프리셋이 아니다” 주장을 자동으로 입증하지 못한다. #13의 caption_len_gap 하나나 target_only 두 결과만으로 해당 홍보 문구를 쓰면 안 된다. 사진만 입력 허용은 ADR-0001의 승인된 축소라 몰래 생긴 드리프트로 판정하지 않는다.

자동 게시·해시태그 추천·인게이지먼트 예측·사진 보정·게이미피케이션은 현재 src/lib·공개 화면에서 실행 기능으로 발견하지 못했다. #65의 태그/음악 등은 미래 기획이고 구현 완료가 아니다. #88 빼기 권고는 명시적 사용자 요청이고 자동 삭제가 아니므로 금지 기능 몰래 추가라고 부르지 않는다. 다만 UI를 범위에서 제외한 서버 권고가 제출 전 투표자에게 어떤 차이를 주는지는 아직 증명되지 않았다.

### 다섯 번째 반복: 판정기가 결과 대신 계약 모양을 승인

[배포 검증 스크립트](../../../scripts/verify-deployed.mjs)는 `7/9 통과, SKIP 2, FAIL 0`을 내고 SKIP만 있을 때 성공 종료할 수 있다. SKIP 경고 자체는 명시적이므로 결과 은폐라고 단정하지 않는다. 문제는 이 출력을 제출 인수로 읽는 순간 발생한다.

1. D2는 샘플 클릭 결과가 아니라 첫 HTML 응답 시간을 잰다. 이번 별도 브라우저 클릭은 이 공백의 일부를 보완했을 뿐이다.
2. D3은 사전 분석된 fixture **3장**을 feed에 직접 보내 업로드·실제 분석·15장 요구를 건너뛴다. 슬롯 수가 0보다 크고 position이 연속이면 PASS다.
3. 근거 배열이 존재하면 D3 PASS다. 별도의 S1 literal 검사도 `uploaded_photo: 선택 순서 1번`이면 rule-only 0개가 된다. **사진을 보고 배치한 적 없어도 근거 있는 큐레이션처럼 체크할 수 있다.** 실제 공개 응답으로 재현했다.
4. D6/S3/S4는 이 스크립트에 없고, ROUTE는 단순 `status !== 404`라 500이나 네트워크 오류 status 0도 통과할 수 있다. 이번 실제 값은 405였으며 그런 오류가 발생했다는 뜻은 아니다.

검증이 내부 계약의 존재를 내부 계약으로 채점하는 순환에 머문다. 고정 테스트를 버릴 필요는 없으나, #77 인수는 외부 입력인 실제 사진·관측 가능한 프로필 차이·사람의 캡션 사실 대조로 독립시켜야 한다. 테스트의 PASS를 제품 주장의 PASS로 복사하지 않는 것이 최소 수정이다.

이번 감사 자체도 15장 API 재생을 실제 15장 업로드로 부르지 않고, 원순서 유지의 구조적 원인과 제한된 대조 결과를 분리했다. 새로운 측정값 조작을 발견했다고 단정하지 않는다. heuristic의 `full_frame`·`midshot`은 상수이고 실측 사진 의미가 아니다. develop은 관측 출처에 따른 제한을 두고 있으므로 이 상수만 발견했다고 새로운 독립 결함이라고 세지 않는다.

### 규약 자체의 잘못된 기억

CLAUDE의 “Production이 develop보다 뒤면 배포 지연” 표현과 스크립트 머리말의 과거 50커밋 설명은 #72에서 철회한 판단을 다시 유도한다. 정본은 브랜치 정책과 **승인된 main SHA + Production deployment SHA + 실제 응답**이다. #69의 과거 “orderFeed 미연결”도 전체 미연결과 특정 분기 우회를 구분해야 한다. 이 감사는 규약을 수정하지 않는다. 코디네이터가 #22/#77 기록을 정리할 때 중복된 과거 진단을 최신 근거 링크로 치환하는 것을 권고한다.

## 부록 B. 독립 공개 요청 재현과 한계

공개 요청 재현(레포 루트, Node fetch):

```js
import { readFile } from 'node:fs/promises';
const photos = JSON.parse(await readFile('test/order.real20.json', 'utf8')).slice(0, 15);
for (const text of ['짧게, 조용하게', '자세하게, 기록하듯']) {
  const r = await fetch('https://project-7klb1.vercel.app/api/feed', {
    method: 'POST', headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ schema_version: '1.0', session_id: 'audit-0918', photos,
      identity: { target: { kind: 'text', text }, current: { kind: 'none' } } }),
  });
  const { feed } = await r.json();
  console.log(r.status, feed.applied_profile.target_profile_id,
    feed.slots.sort((a, b) => a.position - b.position).map(s => s.photo_id),
    feed.slots.filter(s => s.rationale.evidence.every(e => e.kind === 'rule')).length);
}
```

실측 두 요청 모두 200, target `tgt_ft_bc9ca72a` / `tgt_ft_541aaa73`, 정렬된 ID는 둘 다 `ph_01, ph_02, …, ph_15`, rule-only 0. 첫 슬롯 rationale 원문:

```json
{"value":"선택한 순서를 그대로 두었어요. 취향에 맞춰 다시 정렬한 결과는 아니에요.","confidence":1,"evidence":[{"kind":"uploaded_photo","ref":"ph_01","note":"선택 순서 1번"},{"kind":"rule","ref":"order.input_order","note":"사진 계획 또는 제한된 픽셀 분석에서는 새 순서를 추측하지 않는다"}]}
```

실제 JPEG 1장을 `POST /api/analyze` JSON의 `image_base64`로 전송한 별도 요청은 200, 헤더 `x-gyeol-analysis-reason=missing_api_key`, `analysis_source=heuristic`, `model=heuristic-jpeg-dc@1`이었다(응답 시각 `2026-09-18T03:27:34.712Z`). 색·크기는 관측되지만 피사체/장소의 의미 관측 성공을 뜻하지 않는다.

독립 새 Chrome 문맥에서 공개 페이지→샘플 버튼→`그래도 채우기` 표시까지 277ms, 제목 입력 `빛이 머문 자리`, 3장 중 비움 1개 확인. 샘플 클릭으로 `/api` 요청은 없고 사전 작성 예시라는 고지가 보였다. 화면 폭/문서 폭은 모두 390px. 이미지 로딩 완료까지의 별도 시간과 실기기 속도는 측정하지 않았다.

추가 실제 브라우저 업로드: JPEG 15개를 파일 입력에 넣고 `이 사진들로 시작하기`를 눌렀다. analyze 200×15, feed 200, 결과 카드 15개와 원순서 유지 고지, 화면 폭/문서 폭 390/390을 확인했다. 이어 `제목과 문장 제안받기`를 누르자 generate 503과 생성 연결 안 됨 안내가 표시됐으며 사진 15개와 결과 카드는 남았다. 재시도 성공·편집 후 오류 복구까지 검증한 것은 아니다.

첫 자동화는 문장 생성이 자동으로 이어진다고 잘못 가정해 오류 문구 대기 120초가 만료됐다. 화면과 네트워크를 다시 읽어 별도 생성 버튼을 누르는 실제 흐름으로 수정한 뒤 위 결과를 얻었다. 이 검사 실수를 제품의 120초 지연으로 보고하지 않는다.
