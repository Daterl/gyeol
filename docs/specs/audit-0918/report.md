## 5. 제품 드리프트와 검증의 함정

### 가장 큰 드리프트는 문장 결과의 부재

공개 분석은 키 부재로 heuristic이지만 #92 이후 프로필이 있으면 측정 밝기·채도와 사용자 문구를 근거로 순서를 바꾼다. 원순서 보존은 identity가 없는 사진만 경로의 정직한 fallback으로 남아 있다. 현재 핵심 공백은 생성 503과 최신 공개 결과 캡처의 부재다. 사전 작성 샘플 편집을 실생성 증거로 쓰면 안 된다.

원기획 V3는 **동일한 지향·동일 사진에서 CurrentProfile만 달리해** 보정축의 기여를 검증한다. 축소 intent S3의 두 target profile 배열 차이를 통과해도 원기획의 “사람마다 달라진다” 주장을 자동으로 입증하지 못한다. #13의 caption_len_gap 하나나 target_only 결과만으로 해당 홍보 문구를 쓰면 안 된다.

자동 게시·해시태그 추천·인게이지먼트 예측·사진 보정·게이미피케이션은 현재 실행 기능으로 발견하지 못했다. #65의 태그/음악 등은 미래 기획이고 #88은 자동 삭제가 아닌 권고다. 이 확장보다 공개 생성과 제출 인수가 우선이다.

### 판정기가 결과 대신 계약 모양을 승인하는 범위

[배포 검증 스크립트](../../../scripts/verify-deployed.mjs)는 정정 시점에도 `7/9 통과, SKIP 2, FAIL 0`을 내고 종료 코드 0을 반환했다. 원문은 [현재 배포 검증 로그](verify-deployed-2026-09-18.txt)에 있다. SKIP 경고는 명시적이지만 이 출력을 제출 완료로 읽으면 안 된다.

1. D2는 샘플 클릭 결과가 아니라 첫 HTML 응답 시간을 잰다.
2. D3은 사전 분석 fixture 3장을 feed에 보내므로 업로드·실제 분석·15장 요구를 건너뛴다.
3. identity가 없는 이 fixture는 현재도 입력 순서와 `uploaded_photo: 선택 순서 N번` 근거로 D3 검사를 통과한다. 프로필 두 벌의 재배치 증거는 별도 15장 요청으로 확인해야 한다.
4. D6/S3/S4는 스크립트에 없고 ROUTE는 `status !== 404`만 보므로 이번 405도 PASS다.

고정 계약 테스트는 유지하되 #77/#94 인수는 실제 사진, 관측 가능한 프로필 차이, 사람의 캡션 사실 대조로 독립시켜야 한다. 테스트 PASS를 제품 주장 PASS로 복사하지 않는 것이 최소 수정이다.
