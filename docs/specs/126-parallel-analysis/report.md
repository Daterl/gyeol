# #126 — 검증 결과

측정 환경: 로컬 `npm run dev` (PORT=3126), 실 vision 모델(`ANTHROPIC_API_KEY` 사용),
실사진은 `pivot/apify-check/fixtures/images/` 의 29cm 게시물 JPEG.
측정 스크립트는 클라이언트 `upload()` 와 같은 모양으로 `POST /api/analyze` 를 부른다(사진 한 장당 한 번).

> ⚠️ `lib/photo_analysis.js:347` 의 관측 캐시는 **이미지 해시 기준 프로세스 수명 캐시**다.
> 같은 사진을 다시 올리면 모델을 부르지 않는다. 그래서 **측정마다 다른 15장**을 썼고,
> 아래 표에 캐시 적중(`hit`) 수를 그대로 적었다.

## 2. 고친 뒤 — 동시 실행 상한 3가지 (각 1회, 총 3회)

측정 예산이 3회이므로, **3회를 그대로 상한 선택 실험에 썼다.** 3번 재보고 값은 추측으로 고르면
"실측 근거" 가 되지 않기 때문이다.

| 상한 | 사진 | 벽시계 총합 | 성공 | 장당 최대 | 429 | 캐시 적중 |
|---:|---|---:|---:|---:|---|---:|
| 1 (고치기 전) | offset 0 | **155.0초** | 15/15 | 19,159ms | 없음 | 2 |
| 5 | offset 15 | **32.0초** | 15/15 | 13,613ms | 없음 | 0 |
| **8** | offset 30 | **21.3초** | 15/15 | 12,665ms | 없음 | 0 |
| 15 | offset 45 | **15.9초** | 15/15 | 15,877ms | 없음 | 1 |

### 상한을 8 로 고른 근거

1. **5 는 목표를 못 맞춘다.** 32.0초 — 30초를 2초 넘긴다. 15장을 5씩 3파도로 나누면 파도당 약 11초이므로
   구조적으로 33초 부근이고, 다시 재도 넘길 자리다.
2. **8 은 21.3초로 8.7초 여유를 두고 맞춘다.** 15장이 2파도(8+7)로 끝난다.
3. **15 는 더 빠르지만(15.9초) 두 가지를 산다.**
   - **장당 지연이 늘어난다:** 상한 8 에서 최대 12.7초이던 것이 상한 15 에서 15.9초로 올라간다.
     제공자 쪽 대기가 응답 시간에 드러난 것이다. `MODEL_TIMEOUT_MS = 20_000` 까지 여유가
     8 에서 7.3초, 15 에서 4.1초로 좁아진다. 현행 입력 상한은 **15장**이다.
   - **브라우저에서 동시에 들고 있는 바이트가 늘어난다:** 한 장 최대 3MB 기준 8 이면 약 24MB, 15 면 약 45MB 다.
     모바일에서 재는 값이 아직 없으므로 낮은 쪽을 고른다.
4. 세 값 모두에서 **429 는 한 번도 관측되지 않았다.** 즉 8 은 rate limit 여유 안쪽에서 고른 값이고,
   15 를 피한 이유는 429 가 아니라 위 3번이다. 이 구분을 흐리지 않는다.

### 현행 입력 범위
사진은 **3~15장**만 받는다. 상한 15장은 동시 실행 8+7의 두 파도로 처리했고 21.3초로 측정됐다.

## 3. 한 장이 실패할 때의 계약

15장 중 1장(`input_index=5`)을 사진 자체의 문제(415 `UNSUPPORTED_MEDIA_TYPE`)로 실패시켰다.
모델을 부르지 않는 실패이고, 나머지 14장은 1절에서 이미 캐시에 오른 사진이라 추가 모델 호출이 없다.

현행 계약은 부분 성공을 곧바로 feed로 보내지 않는다. 한 장이라도 끝내 실패하면
`ANALYSIS_FAILED`로 실패한 파일을 알리고 **`POST /api/feed`는 호출하지 않는다.** 사용자가 해당 사진을
재시도하거나 삭제한 뒤 다시 제출하면 남은 3~15장을 0..n-1로 매겨 feed를 만든다.

## 6. 안 한 것 / 남은 것

- **진행률 UI 를 만들지 않았다.** P3 이자 이슈 범위 밖이다.
- **`MODEL_TIMEOUT_MS` 를 건드리지 않았다.** 장당 최대가 19.2초로 20초에 붙어 있다는 사실은 기록했다.
  타임아웃을 늘릴지는 서버 함수 실행시간 상한(`maxDuration = 30`)과 함께 정해야 하는 별개 판단이다.
- **모바일 브라우저에서 동시 8요청의 메모리·대역폭을 재지 않았다.** 상한 15 대신 8 을 고른 근거 중 하나가
  이 미측정 위험이다 — 재고 나면 더 올릴 여지가 있다.
