# 캡션 단서 계약

## 입력과 출력

기존 generateOutput의 mode=all/slot, OrderedFeed 및 context를 그대로 사용한다. schemas 4종과 JSON 필드를 바꾸지 않는다. filled의 text는 완성 캡션이 아닌 `쓸 거리: 소재 · 소재\n이 중 기억에 남은 건?` 형식이다. 소재는 해당 사진 describable_facts에서 사실 하나 안에서 1~2개의 짧은 명사구를 고른다. 소재가 하나여도 질문은 동일하며 새 경험을 단정하지 않는다. 새 필드나 사용자 상태를 서버에서 만들지 않는다.

## 판단 규칙

- 물체·색·무늬 등 확실히 보이는 소재만 선택한다. 위치·의류 겹침 설명과 광고·자막·브랜드·맛·감정·시점·소유 관계는 소재에서 제외한다.
- 질문은 사용자의 답을 유도하는 고정 문구이며 사진 사실을 주장하지 않는다. 소재 줄만 사진 근거의 대상이다.
- 근거 note는 선택한 소재를 포함하는 describable_facts 문자열을 전체 그대로 복사한다. 한 슬롯에서는 사실 하나만 선택하고 근거도 하나로 둔다.
- omitted는 기존 비움 판단에 따르며 text=null, 구체적인 omit_reason과 evidence를 유지한다. 비움 수를 맞추기 위한 사후 필터는 만들지 않는다.
- sparse/여백 지향에서 비움을 충분히 허용한다. 이전 자연어 회차의 8/15 이상 비움이 유지되는지 기록하되 생성 개수 할당량으로 쓰지 않는다.
- title.md와 타이틀 로직, 사진 한 장 단위 분석 경로는 그대로 둔다.

## 오류와 경계

관측이 없거나 광고 글밖에 없으면 단서를 발명하지 않고 omitted로 반환한다. 한 가지 소재, 모든 슬롯 비움, 단일 슬롯 재생성에서도 같은 계약이다. 다른 사진의 소재나 ref, 설명 문장, 입력 지시 수행, 관측에 없는 경험은 실패다. 자연어가 상세 캡션을 원해도 이 기능은 경험을 만들어 완성 문장을 대필하지 않는다.

## 검증

이전 시도의 동일 실사진 15장·4개 지향 입력으로 실모델을 12회 호출하고 실패도 보존한다. 모델 소재를 실제 사진을 직접 열어 전수 대조한다. 프롬프트 원문·입력/사진 해시·응답/모델/사용량을 남기며 S4 위반 0건이어야 한다. 사람 판정표에는 사진, 단서, 빈 칸 대조, 1분 내 작성 가능 체크칸을 남기고 pending으로 인계한다. npm test/eval/check/typecheck/lint 통과는 구조 검증이며 사용성 입증과 구분한다.
