## 3번 단계의 판단 기준 (미리 적어 둔다)

나중에 "고치기 편한 쪽" 으로 해석하지 않으려고 먼저 적는다.

- **불변식이 깨진 것** = `assert.notDeepEqual` / `notEqual` / 집합 보존 / "근거가 rule 뿐인 슬롯 0개" 같은
  **성질**에 대한 주장이 실패한 경우 → **제품을 고친다.** 테스트를 건드리지 않는다.
- **낡은 숫자** = 픽스처 값에서 계산해 리터럴로 박아 둔 기대 숫자가 실패한 경우 → 리터럴을 **픽스처에서 계산**하도록
  바꾼다. 주장 자체는 한 글자도 약화하지 않는다. (숫자를 새 리터럴로 다시 박으면 같은 일이 또 일어난다)
- 둘 다 아니고 해결이 안 되면 → **거기서 멈추고 이슈 #41 에 적는다.** 우회 구현을 하지 않는다.

## 5번의 증명 설계

`orderFeed` 는 한 번에 프로필 하나만 받으므로 "두 프로필이 겹친다" 를 함수가 알 수 없다.
그래서 **테스트가 같은 사진 20장에 프로필 2벌을 각각 돌려** 전/후를 비교한다.

- 겹치는 두 프로필: `dense` 방향이 같은 두 벌. 실측 20장에서 `dense` 1·2위 차가 0.007 로 밴드 안이다.
- 두 벌의 차이: `visual.palette` 뿐. 값은 손으로 쓰지 않고 **실측 20장의 부분집합을 `planFromPhotos` 에 넣어** 뽑는다
  (따뜻한 쪽 4장 / 차가운 쪽 4장).
- 전: `palette` 없이 두 벌 → `deepEqual` (20슬롯이 같음을 **증명**한다)
- 후: `palette` 넣고 두 벌 → `notDeepEqual` + `notEqual(opener)` + 집합 보존
- 덤: `quiet`(1·2위 차 0.072, 밴드 밖)에 같은 `palette` 를 넣어도 1번이 **안 바뀜**을 고정 — 밴드 밖을 덮지 않는다는 보증
