- 탐색 배치와 본 배치, 3장 생성의 일부 실행 시간이 겹친다. 격리된 부하 벤치마크가 아니며 지연 차이를 사진 크기나 처리 방식의 효과로 해석하지 않는다.
- `.env.local`의 기존 키와 workspace 설정을 프로세스에만 로드했다. 비밀값·로컬 절대경로·원본 사진은 보고서에 넣지 않았다.

```sh
# 사진 경로를 정확히 3개 또는 15개 전달한다. 1개 진단 실행도 지원한다.
node --env-file=/private/path/.env.local scripts/measure-model.js photo1.jpg photo2.jpg photo3.jpg > analysis-3.json
# 저장된 성공 분석을 재사용해 빈 지향/작성 지향을 각각 생성한다.
node --env-file=/private/path/.env.local scripts/measure-generation.js analysis-3.json > generation-3.json
```

각 JSON은 실제 실행 출력이다. `MEASURED`는 호출 성공을 뜻하며 품질·청구·배포 PASS가 아니다. `total_ms`는 사전 파일 읽기/메타데이터 검증 이후의 분석 루프 전체, `wall_ms`는 사진 처리 전체, `execution.elapsed_ms`는 모델 조회와 메시지 요청 구간이다. 생성 `wall_ms`는 피드 구성과 생성을 포함한다. 생성은 저장된 분석을 사용했으므로 분석 시간을 포함하지 않는다.

## 비용·배포·반복 조건의 정확한 잔여

- **실제 청구액 PENDING:** 응답 usage는 보존했지만 해당 실행에 대응하는 청구 내역을 확보하지 않았다. 읽은 실행 환경에 `ANTHROPIC_ADMIN_API_KEY`가 없고 청구 내역도 제공되지 않았다. `actual_usd=null`이며 0달러를 뜻하지 않는다.
- **추정 금액 PENDING:** 검증된 계정/모델 단가를 이번 작업에서 확보하지 않아 `estimated_usd=null`이다. 토큰 수나 과거 3장 평균을 청구액 또는 실제 15장 값으로 변환하지 않았다.
- **Vercel PENDING:** 로컬 파일은 `/api/analyze`의 `maxDuration=30`을 선언하지만 실제 프로젝트 설정·배포 함수 왕복을 이번 실행에서 확인하지 않았다. 실행 환경에 `VERCEL_TOKEN`도 없다. #6의 배포 증거와 연결하기 전 A1 PASS/FAIL을 선언하지 않는다.
- **15장 × 3회 및 축소 전후 비교 PENDING:** 이번 고유 15장 실행은 1회이며 세 번 성공 조건을 대체하지 않는다. 탐색 회차는 중복이 있어 추가 성공 회차로 세지 않는다. 다운스케일 전후 품질 비교는 수행하지 않았고 기존 #98 잔여 조건을 닫지 않는다.

## 코드·회귀 증거

측정기에서 3장 입력을 지원하고 전 배치 입력을 유료 호출 전에 검사한다. 입력 해시·크기·해상도, 원본 대조용 분석, 안전한 오류 코드, 부분 완료/실패/미시도 수를 남긴다. timeout/계약 실패 뒤 나머지 사진은 계속 측정하지만 계정·설정·네트워크 오류는 배치를 중단한다. 캐시/heuristic 결과는 실모델 성공으로 집계하지 않는다. 생성 측정기는 완전한 실모델 분석 보고서만 재사용한다.

Node `v24.21.0`: `npm test` 216/216, `npm run eval`, `npm run check`, `npm run lint`, `npm run typecheck` PASS. Node 22에서의 실호출과 Node 24 회귀 검증을 구분한다. 기존 [PR #45](https://github.com/Daterl/gyeol/pull/45), [PR #67](https://github.com/Daterl/gyeol/pull/67)의 missing-key/JSON/계약/timeout/실패 캐시/복구/thinking 블록 검증도 현재 `test/model.test.js`·`test/photo_analysis.test.js`에서 통과했다. 오류 검증은 주입 테스트이며 실제 제공자 장애를 일으킨 검증은 아니다.

검증 한계: Biome 설정은 `scripts/`와 `test/`를 검사하지 않으므로 변경 스크립트에 `node --check`와 직접 회귀 테스트를 별도로 실행했다. 새 의존성·앱 코드·배포 설정 변경은 없다. 기존 `package-lock.json` 변경은 이번 커밋에서 제외한다.

측정 독립성 점검(mandela): 계약/자기 evidence 검사는 모델 관측을 사실 정답으로 쓰면 순환 검증이다. 그래서 원본 대조 결과를 별도 기록하고 품질 PASS를 보류했다. 동일 표본의 1회 관측은 일반화하지 않는다. 기존 명세의 과거 PENDING 기록은 삭제하지 않고 현재 보고서에 연결했다. 독립적인 새 컨텍스트 리뷰와 사람 인수는 수행하지 않았다.
