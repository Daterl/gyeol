# #101 캡션 씨앗 품질 인수 — 실모델 회차와 실사진 대조

이 폴더는 **현재 develop 계약(#123 한 사실·한 소재 + 한 번의 재선택)으로 돌린 실모델 회차와 원본 사진 15장 대조 결과**다. [`101-caption-quality`](../101-caption-quality/)의 감사·실패 기록, [`123-generation`](../123-generation/)의 생성 계약 인수, [`remaining-quality`](../remaining-quality/)의 오프라인 재생(가짜 응답)과는 성격이 다르다. 여기 있는 생성 결과는 전부 실호출이다.

재현:

```sh
node scripts/caption-seed-acceptance.mjs        # 기록된 회차를 모델 호출 0회로 다시 채점 → review.md 재생성
node --test test/caption-seed-acceptance.test.js
```

`scripts/caption-seed-acceptance.mjs`의 `runLive()`가 회차를 만든다. 채점 코드에는 모델 호출이 없어서 기록만으로 다시 검증된다.

## 무엇을 실제로 돌렸나

- 사진: 감사 회차와 **같은 실사진 15장**. `docs/specs/101-caption-quality/inputs.json`의 `file_ref`가 원본을 지목하며, 그 파일을 **vision 모델로 다시 분석**한 관측을 썼다.
- 지향 4종(레퍼런스 / 자연어 / 사진만 / 보정) × 4회 = **16회 시도, 12회 성공**. 실모델 회차 판정은 그래서 `PASS`가 아니라 **`PARTIAL`**이며, 실패가 한 건이라도 있으면 `validateArtifact`가 `PASS` 기록을 거부한다. 생성 모델은 `config/models.json`의 `output_model`.
- 사진 원본(인스타 수집물)은 커밋하지 않는다. `file_ref`로만 가리킨다.
- [`live-evidence.json`](live-evidence.json)에 입력 관측·feed·응답 원문·실패 원인·채점·판정을, [`review.md`](review.md)에 회차별 타이틀 전수와 슬롯별 실사진 대조표를 남긴다.

## 이슈 완료 조건별 결과

| 완료 조건 | 결과 | 근거 |
|---|---|---|
| `caption.md`에 "관측 사실을 나열하지 않는다" 규정 | 충족 | 두 줄 단서 형식·소재 1개·설명문 금지가 프롬프트와 `MODEL_CONTRACT` 양쪽에 있다 |
| 같은 실사진 15장 재생성 후 과반이 "고쳐서 쓸 수 있다" | **PENDING** | 에이전트가 15개 슬롯 중 14개를 USABLE로 봤다. 다만 그중 수식 없는 홑낱말 소재(`접시` `노트`)가 있어 "쓸 거리로 쓸모 있다"는 이 숫자만으로 성립하지 않는다. 사람 판정 대상 |
| 금지어 0건 유지 | 충족 | 12회 전 슬롯에서 금지어 0 |
| S4(원문에 없는 소재) 0건 유지 | **관측 원문 대조 범위에서만 충족** | 소재가 그 슬롯 **관측문**과 글자 단위로 다른 경우 0건. 관측 자체가 원본 사진과 다르면 이 검사는 통과한다 — 실제로 cq_13에서 통과했고 원본 사진 대조에서 1건이 걸렸다 |
| 타이틀이 사진 한 장의 글귀·숫자를 묶음 사실로 올리지 않음 | 충족 | 12회 타이틀 전수 기록, 숫자 0건·발췌 0건. 띄어쓰기·문장부호를 지운 뒤 대조하고 두 자 이상 숫자도 본다 |
| evidence `note`가 그 슬롯 원문에서만 나옴 | 충족 | 원문 불일치 0건, 감정·계절·의도 어휘 0건 |

전후 비교는 [`review.md`](review.md) 마지막 표에 있다. 감사 회차의 설명문(“초록 접시에 튀김과 떡, 분홍 종이봉투에는…”)이 두 줄 단서로 바뀌었다.

## 이 브랜치가 더한 것

생성 계약의 본체(모델 근거 열거형을 `rule`로 제한, `fact_index` 명시, 거부 후 한 번의 재선택)는 **develop의 #123 작업**이다. 이 브랜치는 그 위에 #101 완료 조건이 요구하는 두 가지를 더한다.

1. **타이틀이 사진 한 장의 글귀를 묶음 전체의 사실로 올리는 경로를 런타임에서 막는다.** 감사에서 `가을 브랜드 25곳`(사진 한 장의 광고 문구 "가을 맛집 브랜드 25")과 `가을 시작`(cq_07의 "이제 진짜 가을 시작이야")이 나왔다. 다섯 자 이상 이어진 발췌를 거부하되, 띄어쓰기·문장부호를 지운 뒤 대조하므로 `가을맛집`처럼 붙여 써도 같은 발췌다. 사진 글귀에 있던 **두 자 이상의 숫자**는 다섯 자에 못 미쳐도 거부한다(`25곳`). 한 자리 숫자와 짧은 낱말 겹침은 발췌로 보지 않는다 — `사진 3장`처럼 묶음 수치와 구별할 근거가 없다. 채점 코드도 같은 판정 함수를 쓴다.
2. **`MODEL_CONTRACT`가 걸린 규칙을 `cause`로 전달한다.** 사용자 메시지는 그대로다. 이것이 없으면 실호출 실패를 로그만 보고 진단할 수 없다 — 이번 측정에서 실패 4건의 원인을 가른 것도 이 값이다.

## 알려진 한계 — 이 기록이 증명하지 않는 것

- **사람의 게시 가능 판정은 없다.** 에이전트가 원본 이미지를 직접 열어 판정했고 그 칸은 `agent`로 표시했다. `human` 칸은 비어 있고 `validateArtifact`가 채워진 사람 판정을 거부한다. 에이전트 판정을 사람 인수로 읽지 않는다.
- **에이전트 판정 14/15 USABLE을 "쓸모 있다"로 읽지 않는다.** 149개 단서 중 7개가 수식 없는 홑낱말 소재로, 관측문을 그대로 옮긴 alt-text에 가깝다. 사실이지만 사용자가 고쳐 쓸 거리로 충분한지는 사람만 판정한다.
- **관측 원문 대조와 원본 사진 대조는 다른 축이다.** `unsupported_materials`(원문 대조) 0건은 원본 사진과 맞다는 뜻이 아니다. 원본 사진 대조에서는 1건(cq_13)이 사실과 다르다.
- **시도 16회 중 4회가 실패한다.** 전부 `Hint seed is not a verbatim phrase from its evidence`이며, develop의 재선택 한 번으로도 회복되지 않은 경우다. `MODEL_CONTRACT`는 재시도 가능으로 응답한다. 성공률 12/16을 품질 통과로 읽지 않는다.
- **관측 단계의 오류는 이 게이트가 못 잡는다.** cq_11의 겉옷은 검은 바탕에 크림색 양털인데 관측이 `흰색 털 재킷`이라 했고, 단서는 그 원문을 충실히 발췌했다. 원문 대조만으로는 통과한다. 사진 대조가 필요한 이유이며, [#129 사실성 감사](../../submission/factuality-audit.md)가 cq_10에서 같은 종류의 오차를 따로 기록했다.
- **소재가 한 개로 줄면서 단서가 밋밋해진 자리가 있다**(cq_04 `접시`). 참이지만 쓸 거리로는 약하다. 소재 개수와 유용성의 균형은 사람 판정 대상이다.
- 타이틀에 `계절`처럼 관측에 있는 낱말이 들어가는 경우가 있다. 낱말 단위의 근거 판정은 자동화하지 않았고 사람 검토 대상이다.
- 화면 조작(드래그 재배치, 비움 카드의 `[그래도 채우기]`)과 실제 배포 URL 확인은 이 폴더의 범위가 아니다.
- 프로덕션 빌드의 prompt 번들 문제(**#183**)는 develop의 #186으로 고쳐졌고 이 브랜치도 그 위에 있다. `npm run test:production`이 13항목 전부 PASS 하는 것으로 이 변경이 #183을 되돌리지 않음을 확인했다. 다만 위 실모델 회차는 **순수 Node 경로**에서 돌린 것이고 배포 환경 자체의 인수는 아니다.
