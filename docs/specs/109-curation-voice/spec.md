# 계약과 정확성
입력은 기존 PhotoAnalysis 3~20장과 프로필이다. 출력은 기존 OrderedFeed 그대로다.
새 필드나 schemas 변경 없이 첫 슬롯 rationale.value 앞 문장에 묶음 컨셉을 넣는다.
색의 진하기 범위가 0.25 이상이면 옅고 짙은 색의 흐름, 아니면 명암 범위가 0.25 이상이면 밝고 어두운 화면의 흐름을 제안한다.
0.25는 관측 결과가 아닌 보수적인 문장 선택 설계 상수다. 그 미만이면 공통 컨셉을 정하기 어렵다고 명시한다.
컨셉에 쓴 전 사진의 측정 근거는 첫 슬롯 evidence에 둔다. 첫 슬롯 이외 비교 문장에는 앞 사진 근거를 둔다.
앞 사진과 밝기 또는 진하기 차이가 0.12 이상일 때만 방향을 말한다. 이하에서는 역할만 설명한다.
장소·시간·감정·피사체를 색에서 지어내지 않는다. 모델이나 사용자 자유문구를 그대로 복사하지 않는다.
기존 점수·동점·보너스 선택 설명과 규칙은 evidence 안에 보존하고 순서·caption_inputs는 유지한다.
지향 없는 사진 입력은 기존 입력 순서를 유지하며 컨셉만 첫 설명에 추가한다.
금지어 탐지는 rationale.value만 대상으로 한다. 근거 안 측정값과 규칙은 유지되어야 한다.
실사진 15장 모두를 직접 열고 대조한다. 사람 적합성 통과율은 실제 응답 전까지 미측정이다.

## 리뷰 2회차 계약 변경 (2026-09-18)
컨셉은 `OrderedFeed.concept` 로 옮긴다. `Claim<nonempty string>` 이며 **선택적(optional)** 이다.
슬롯의 rationale.value 는 첫 구현 이전으로 돌아가 자리 설명만 담는다. 컨셉 문장을 앞에 붙이지 않는다.

정확성 기준 — 다음을 하면 틀린 것이다.
- 컨셉이 특정 슬롯에 저장되는 것. 순서를 바꿨을 때 컨셉이 따라 움직이면 틀렸다.
- 채도 범위와 밝기 범위가 모두 0.25 미만인데 `concept` 가 존재하는 것. 이때는 필드를 생략한다.
- `concept` 의 value 나 evidence 가 실제 PhotoAnalysis 재계산 결과와 다른 것.
  caller 가 값을 위조해 공개 근거로 승격시키는 경로를 만들지 않는다 (#107 revert 교훈).
- 근거가 값과 다른 말을 하는 것. 미달이면 값이 없으므로 "비운다" 는 근거도 존재하지 않는다.

경계값 — 채도 범위 0.25 = 컨셉 있음(옅은/짙은), 0.2499 이고 밝기 범위도 미달 = 필드 생략.
evidence 는 photo_id 오름차순으로 고정한다. 입력 배열 순서가 달라도 같은 피드가 나와야 검증이 재계산과 일치한다.

`schemas/ordered_feed.md` 에는 `concept` 가 아직 적혀 있지 않다. 스키마 4종은 이 PR 에서 바꾸지 않고
추가가 필요한 한 줄을 PR 본문에 적는다 (SOP: 스키마는 두 사람 합의 대상).

모델 경계 — `lib/output-generation.js` 의 `forModelSlot` 은 슬롯에서 `{position, photo_id,
caption_inputs.describable_facts}` 만 추려 모델에 넘기고, 모델 입력은 `{mode, applied_profile, slots}` 다.
`concept` 는 피드 최상위 필드이므로 모델 입력에 **포함되지 않는다.** 즉 이 변경의 모델 입력 증가량은 0 이다.
