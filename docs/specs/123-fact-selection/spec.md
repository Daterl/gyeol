# #123 사진 근거 선택 안정화

목표: 현재 G4 계약의 3장·15장 생성에서 모델의 근거 요약 때문에 전체 응답이 실패하지 않도록 한다. 공개 응답 계약은 유지한다.

- 모델 내부 응답의 `fact_index`는 해당 사진의 관측 사실 배열에서 0부터 시작하는 번호다. 서버가 근거 원문을 구성하고 응답에서 번호를 제거한다.
- 번호가 있는 응답은 범위와 타입을 먼저 검사한다. 다른 사진의 근거·복수 사진 근거는 거부한다.
- 단서는 기존 형식·금지 표현 검사를 통과해야 한다. 선택된 사실의 짧은 구절은 보존하고, 요약하거나 다른 사실에서 뽑아 글자 일치가 깨진 단서는 거부한다. 번호 선택은 근거만 구성하며 단서 문장을 만들거나 바꾸지 않는다.
- 사실이 없으면 번호 0과 비움만 허용하며 고정 한계 문구를 사용한다. 사실 없는 seed는 거부한다.
- 내용 없는 선택적 rule 근거만 제거한다. 사진 근거는 항상 서버가 제공하고, 다른 잘못된 근거는 검증에서 거부한다.
- 번호 없는 기존 응답의 엄격한 검증과 유일한 70% 부분문자열 복원은 유지한다.
- 기존 회귀 테스트를 삭제하거나 완화하지 않는다. all/slot, 잘못된 번호, 사진 참조, 빈 사실, 금지 표현을 새 회귀 테스트로 검증한다.

검증: Node 테스트, check/eval/lint/typecheck/UI/build. 실제 모델 3장·15장 반복 성공 여부는 별도 기록하며, 로컬 성공을 Preview/Production 성공으로 기록하지 않는다. 강제 비움 개수는 최신 ADR-0008의 완료 조건이 아니다.

범위: `lib/output-generation.js`, `prompts/output/caption.md`, `test/generate.test.js`. 기존 미커밋 진단 파일과 자동 생성 파일은 보존한다.

## 작업 출처와 경계

기존 vdev 체크아웃의 `4e6c901` 위 미커밋 패치에서 위 세 파일과 이 명세만 이식했다. 원본 체크아웃은 수정하지 않았으며 진단 파일·설정·비밀 값은 복사하지 않았다. 추가로 모델이 보낸 사진 근거의 잘못된 타입이나 빈 문구를 정규화 전에 거부하며, 프롬프트의 마지막 점검도 번호 선택 계약에 맞췄다. CodeRabbit와 독립 검토에서 지적한 전체 관측 문장으로의 단서 대체는 제거하여 기존 짧은 단서 검증을 유지한다.

[ADR-0008](../../adr/0008-public-profile-curation-and-sharing.md)에 따른 강제 비움 제거는 이 PR 다음 G4 작업에서 진행한다. 이 변경은 기존 비움 정책을 바꾸지 않으며, 실모델·배포 환경의 반복 성공을 증명하지 않는다.
