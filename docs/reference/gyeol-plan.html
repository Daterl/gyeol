01 /

‘올릴 마음’은 이미 있다. 막히는 건 순서다.

경쟁은 다른 AI 제품이 아니라 “지금 이대로 하는 것”입니다.

누구 — 1차 타깃 1명

확정 결정 부계(부계정)를 운영하는 20대 일상 기록러. 팔로워 수가 아니라 계정을 하나 더 파서 따로 운영한다는 행동으로 모읍니다.

“본계는 관리하느라 피곤해서 부계를 팠는데,
부계도 슬슬 정리하고 싶어졌어요.”

〈가상 발언〉 설명을 위한 가상 발언입니다. 실제 사용자 인터뷰 인용이 아닙니다.

이 층을 고른 근거 4개

  • 모집단이 확인됐다. 한국 20대의 복수 계정 운영은 보고된 흐름이고, 인스타그램은 앱 하나에서 최대 5개 계정 전환을 공식 지원합니다. 출처 확인
  • 경쟁 밀도가 가장 낮다. Later·Planoly·Preview·Buffer는 전부 1인 브랜드/소상공인을 정조준합니다. 이 층에는 아무도 서 있지 않습니다.
  • 핵심 가설과 정합한다. 특히 “설명 없음도 유효한 결과”가 이 층의 감성과 맞습니다.
  • 데모 리스크가 오히려 낮다. 부계는 대부분 비공개·개인 계정이라 Instagram Graph API(인스타그램이 외부 프로그램에 데이터를 주는 통로)로 애초에 못 읽습니다. 연동 없는 경로가 “보험”이 아니라 이 타깃에게는 정상 경로입니다.

왜 “되고 싶은 나”를 먼저 묻는가

부계가 비공개라 API로 못 읽는다면, “본인 기존 피드”를 주축에 두는 설계는 1차 타깃에게 주 경로가 상시 죽어 있는 설계입니다. 두 가지가 더 있습니다.

  • 부계를 판 행위 자체가 이미 지향의 표현이다. 본계와 다르게 하고 싶어서 계정을 하나 더 만든 사람에게 “기존 부계 피드대로 해드릴까요”는 거의 동어반복입니다. 그 사람이 제품을 여는 이유는 부계의 결이 아직 안 굳었기 때문입니다.
  • 부계는 표본이 얇다. 현재를 주축에 두면 표본 부족이 곧 제품 실패지만, 지향을 주축에 두면 표본 부족은 “보정 없이 지향만 반영함”이라는 정직한 열화로 끝납니다.
⚠ 미검증 가정 — 위 두 문장은 조사에서 확인한 사실이 아니라 본 기획의 추론입니다. U4(부계의 정의와 큐레이션 니즈가 모순될 수 있음)와 같은 성격이며, 검증 V1 인터뷰에서 함께 묻습니다.

언제 — 트리거 순간 3개

문제는 “인스타를 잘하고 싶다”는 상시 욕구가 아닙니다. 아래 세 순간에만 발생하고, 셋은 같은 세션 안에서 연달아 일어납니다. 그래서 순서·타이틀·캡션을 한 번에 내야 합니다.

트리거사용자 머릿속근거
T1 여행·모임·전시가 끝나고 갤러리에 사진 10~20장이 남았을 때“올리긴 올릴 건데… 어떤 순서로?”photo dump(한 번에 5~10장을 캐주얼하게 올리는 포맷)가 이 층의 행동이고, 캐러셀이 20장까지 늘면서 이 문제는 최근 2배가 됐습니다. 캐러셀 20장 확대
T2 캐러셀 1번 장을 고르는 순간“첫 장이 스와이프를 번다는 건 아는데, 뭐가 1번이지?”캐러셀 서사 구조는 이미 언어화되어 유통 중입니다 — 단 텍스트 슬라이드 도구들에서만.

아이덴티티 만들기 — 두 축과 그 합성

확정 결정 프로필은 하나가 아니라 둘입니다. “되고 싶은 나”가 주축이고, “원래 내가 올려온 방식”이 보정축입니다. 두 축은 F1 안의 구조이지 별도 기능이 아닙니다.

주축 · 입력은 선택 TargetProfile — 지향

되고 싶은 결. 레퍼런스에서 뽑습니다. 안 주면 제품이 만듭니다(아래 “지향 입력이 없을 때”).

채울 수 있는 것: 시각 특성(색조·명도·여백·스케일·피사체·1번 장 구도).
입력이 인스타 URL이면 언어 특성까지 채웁니다. 사진 업로드·자연어로 들어오면 언어는 비거나 선언값뿐입니다.

보정축 · 입력은 필수 CurrentProfile — 현재

원래 내가 올려온 방식. 입력은 필수(기본값) — 인스타 URL, 또는 내 기존 게시물 사진 업로드.

채울 수 있는 것: 시각 + 언어 특성(캡션 길이·이모지·말끝·줄바꿈·캡션 없음 비율) + 게시 리듬.

“주축”과 “필수”가 서로 다른 축에 있습니다. 혼동하지 않도록 갈라 둡니다.
주축 = 결과가 무엇을 향하는가(최종 출력이 따르는 결) → TargetProfile.  ·  필수 입력 = 사용자에게 무엇을 반드시 받는가 → CurrentProfile.
모순이 아닙니다. “기존 내 피드를 분석해야 그걸 기반으로 방향성까지 제시할 수 있다” — 지향을 내려면 현재를 알아야 하므로, 현재가 입력에서 먼저 필요합니다. 지향 입력은 제품이 만든 제안을 덮어쓰는 선택지입니다. TargetProfile이 빈 채로 결과가 나가지는 않습니다 — 사용자가 안 주면 제품이 만듭니다. 그래서 F2·F3가 읽는 것은 그대로입니다.

합성 결과 — applied_profile + deltas

applied_profile은 F2·F3가 실제로 읽는 것이고, deltas는 간극 카드의 원본입니다. 둘 다 F2가 내보내는 OrderedFeed 안에 실려 F3로 넘어갑니다. 필드 하나는 값 + 출처(from) + 근거를 함께 갖습니다.

이 구조에서 가장 중요한 한 줄 — 그리고 이번 개정에서 바뀐 한 줄:
이전에는 “언어 축의 유일한 실측 소스는 CurrentProfile이다”였습니다. 근거는 남의 계정 캡션을 읽을 수단이 없다였습니다.

그래도 보정축은 버리지 않습니다. 이유가 하나 줄었을 뿐 사라지지 않았습니다. ① 언어 축의 유일한 실측 소스 — URL 경로가 열리면서 “유일”은 깨졌습니다. 정직하게 인정합니다. ② 1차 타깃(부계 운영자)에게는 CurrentProfile의 URL 경로가 대부분 막혀 있습니다(01절 타깃 · 아래 URL 절). ③ “당신이 원래 얼마나 비웠는가”는 원리적으로 지향 축에서 나올 수 없습니다 — 레퍼런스가 얼마나 비웠는지는 비교 대상이지 그 질문의 답이 아닙니다. ④ 보정축이 없으면 간극 카드가 0개이고, 그러면 제품이 프리셋으로 읽힙니다(05절).

열화 시퀀스 — 축마다 따로 정의한다

열화(degradation) = 좋은 경로가 막혔을 때 제품이 죽지 않고 한 단계 아래 경로로 내려가는 설계.

주축 TargetProfile — 입력은 선택

  • T0레퍼런스 인스타 URL 공개 계정 URL 1개. → 시각 + 언어 특성까지 실측. 캐러셀 배열로 첫 장 경향도 얻습니다. 실패 트리거: 비공개 계정 / 수집 실패 / 대기 상한 초과
  • T1레퍼런스 사진 업로드 “이런 느낌” 사진 3~9장. → 시각 특성. 언어는 빔. 실패 트리거: 사실상 없음(로컬 파일)
  • T2자연어 입력 “차분하고 여백 많은 느낌으로”. 근거는 사용자 발언 원문 하나뿐 → 근거 강도 낮음

넷은 배타가 아닙니다. 여럿 있으면 다 씁니다. 지향을 하나도 안 줘도 막지 않습니다 — T3이 그 자리를 받고, 지향 입력은 그 제안을 덮어쓰는 선택지입니다. 자연어는 사진이 말하지 못하는 의도(“설명은 최대한 줄이고 싶다”)를 담는 자리입니다.

보정축 CurrentProfile — 입력은 필수(기본값)

  • C0내 인스타 URL 내 공개 계정 URL 1개. → 시각 + 언어 + 게시 리듬 실측. ⚠ 1차 타깃의 부계에는 대부분 안 열립니다
  • C1Instagram API 연동을 이미 붙였을 때만. 크리티컬 패스 아님. ⚠ 비공개 부계에는 쓸 수 없습니다 — 프로페셔널 전환이 필수인데 전환하면 계정이 공개로 바뀝니다. 실패 트리거: HTTP 에러 / 8초 타임아웃 / 토큰 만료 / 현장 네트워크 차단

  • C3내 기존 게시물 사진 직접 업로드 3~9장 + (선택) “이때 뭐라고 쓰셨는지 기억나면 붙여넣어 주세요”. 1차 타깃의 실질적 기본 경로이며, 열화가 아니라 C0과 동등한 경로입니다

필수 입력이 막히는 쪽이 하필 1차 타깃입니다. 내 부계가 비공개면 URL도 공식 연동도 안 열립니다(연동은 프로페셔널 전환을 요구하는데, 전환하면 계정이 공개로 바뀌고 대기 중 팔로우 요청이 자동 수락됩니다 — 부계 운영자가 받아들일 대가가 아닙니다). 그래서 “내 기존 게시물 사진 업로드”는 대안이 아니라 이 타깃의 기본 경로이고, 업로드 마찰을 “사진 3장”까지 낮추는 것이 제품의 생사입니다. 10장을 요구하면 1차 타깃에게 제품이 시작되지 않습니다.

비공개 계정 — 이 제약은 그대로입니다. 이 수집 서비스도 비공개 피드를 지원 대상으로 삼지 않고, 공식 API도 못 읽습니다(프로페셔널 전환이 필수인데 전환하면 계정이 공개로 바뀝니다). 비공개 계정을 읽는 경로는 여전히 0개입니다. 그래서 UI는 URL 칸 옆에 “공개 계정만 읽을 수 있어요”를 입력 전에 적고, 사진 업로드 칸을 같은 화면에 나란히 둡니다.

1차 타깃의 부계는 대부분 비공개다 — 그런데 왜 URL이 1순위인가

01절이 1차 타깃을 고른 근거 중 하나가 “부계는 대부분 비공개·개인 계정이라 API로 애초에 못 읽는다”였습니다. 그 사실과 “URL이 입력 1순위”는 나란히 놓으면 모순처럼 보입니다. 모순이 아닙니다 — 두 축이 서로 다른 계정을 가리키기 때문이고, 그 비대칭이 우리에게 유리한 방향입니다.

축가리키는 계정공개일 확률이 타깃에게 URL 경로가 열리는가
주축 TargetProfile남의 계정 — 내가 동경해서 참고하는 곳높다열린다. 실질적 1순위가 맞다
보정축 CurrentProfile내 부계 — 내가 운영하는 곳낮다대부분 막힌다. 사진 업로드가 실질적 1순위다
⚠ 미검증 가정 — “레퍼런스로 삼는 계정은 대부분 공개다” 논리는 이렇습니다: 레퍼런스로 삼는 계정은 내가 볼 수 있어야 동경도 생깁니다. 비공개 계정은 애초에 남에게 안 보이므로 레퍼런스 후보로 떠오르지 않습니다. 그러나 이 문장은 추론이며 조사로 확인하지 않았습니다. 주축 1순위가 실제로 열려 있다는 판단이 이 추론 위에 서 있습니다. V1 인터뷰에 한 문항을 더해 확인합니다 — “참고하는 계정 있으세요? 그 계정 지금 열어서 보여주실 수 있어요?”(열리면 공개 계정입니다).

보정축 쪽은 유리하지 않습니다. 그대로 씁니다. 내 부계가 비공개면 수집 서비스로도 못 읽고, 공식 API도 못 읽습니다(프로페셔널로 바꾸면 계정이 공개가 되고 대기 중 팔로우 요청이 자동 수락됩니다 — 부계 운영자가 받아들일 수 있는 대가가 아닙니다). 즉 이 타깃에게 CurrentProfile의 현실적 경로는 URL도 연동도 아니고 “내 사진 직접 업로드” 하나입니다.

  1. URL을 두 축 모두의 1순위로 두는 것은 맞습니다. 주축에서는 실제로 가장 자주 쓰일 경로이고, 보정축에서도 본계·공개 부계 운영자에게는 열립니다.
  2. 다만 1차 타깃의 보정축에서는 URL이 대부분 실패합니다. 그래서 UI는 “공개 계정만 읽을 수 있어요”를 에러가 아니라 사전 안내로 먼저 적고, 사진 업로드 칸을 URL 칸과 같은 화면에 나란히 둡니다. 실패한 뒤에 다른 칸으로 보내면 그건 이탈입니다.
  3. 이 비대칭은 “되고 싶은 나가 주축”이라는 결정을 약화시키지 않고 강화합니다. 주축은 URL로 실측이 열리고, 보정축은 원래부터 “없어도 제품이 동작하는” 축입니다. 크리티컬 패스에는 열리는 쪽만 놓여 있습니다.

대기와 비용 — 수집을 제품 설계 제약으로 받는다

실측이 준 숫자는 둘입니다: 약 74.6초, $0.27(게시물 100개, 공개 계정 1건). 둘 다 사용자가 체감하는 제약이므로 설계에 반영합니다. 아래 결정은 실측에 있는 숫자만 쓰고, 없는 숫자는 만들지 않습니다.

#결정근거
D1URL 수집은 사진 분석과 병렬로 돌린다진입 화면에서 사진과 URL을 함께 받으므로(02절) 순차로 돌릴 이유가 없습니다. 체감 대기는 둘 중 긴 쪽입니다.
D2수집 게시물 수를 30으로 고정한다. 100을 쓰지 않는다사용법 문서가 “처음엔 3개로 확인하고 확인 후 30 등으로 올린다”를 권합니다. 같은 요율 단순 계산으로 30개 = $0.081.
D3사용자에게 고지하는 상한은 “최대 약 75초”다실측 74.6초가 우리가 가진 유일한 시간 근거입니다. 줄어들 것으로 기대하지만 기대를 숫자로 약속하지 않습니다(U17).
D4분석 중 화면은 “지금 무엇을 하는 중인지”만 적는다. 가짜 진행바로 시간을 끌지 않는다P3(진행률 UI 금지)와 충돌하지 않습니다 — P3이 금지하는 것은 “3/3 완성” 같은 캡션 채우기 압력 UI입니다.
D5데모에서는 사전 수집 스냅샷을 기본 경로로 쓴다. 무대에서 라이브 수집을 돌리지 않는다대기 0초, 비용 0, 네트워크 의존 0. “실현 가능성” 점수를 지키는 것이 이제는 “연동을 안 한다”가 아니라 “무대에서 라이브 수집을 돌리지 않는다”입니다.
D6한 세션의 URL 입력은 최대 2개(주축 1 + 보정축 1)비용이 실비입니다(결제 기능이 없으므로 06절, 해커톤 기간에는 팀이 부담합니다). 그리고 여러 계정을 합치면 그 자체로 틀린 프로필입니다(아래 정확성 기준).
D7수집 결과는 세션이 끝나면 버린다. 보관하는 것은 데모용 스냅샷뿐이고 보관 기간을 미리 정한다사용법 문서가 “이미지 URL을 영구 주소로 취급하지 않는다 … 보관 기간을 정한다”고 명시합니다. 계정/로그인이 없으므로(06절) 세션을 넘겨 보관할 근거도 없습니다.
왜 “75초 기다리게 한다”를 그냥 받아들였나. 대안 둘을 검토하고 뺐습니다 — ① 먼저 잠정 결과를 내고 수집이 끝나면 갱신: 결과가 눈앞에서 두 번 바뀌는 경험이고, 무엇보다 새 기능이 됩니다(기능 3개 규율 위반). ② 수집을 사전에만 돌리기: 그러면 사용자가 자기 레퍼런스를 못 넣고, 그건 이 경로를 되살린 이유 자체를 지웁니다. 남은 정직한 선택은 “기다리게 하되 얼마나 걸리는지 먼저 말하는 것”입니다. 대기가 싫은 사용자에게는 사진 업로드·자연어가 즉시 경로로 같은 화면에 있습니다.

④ 약관과 법적 위치 — “그거 합법인가요”라는 질문에

준비된 답 “공개 계정의 데이터를, 사용자가 직접 넣은 URL에 대해서만, 제3자 수집 서비스를 통해 가져옵니다. 비공개 계정은 읽지 않고 읽을 수도 없습니다. 원본 게시물 링크를 근거로 함께 표시하고, 수집 결과는 세션이 끝나면 버립니다. 다만 Meta 약관 관점에서 이 경로가 적법한지는 아직 법적 검토를 받지 않았습니다. 그래서 기획서에 미검증 가정 U16으로 올려 뒀고, URL 없이도 제품이 끝까지 동작하는 경로를 1순위 아래에 그대로 남겨 뒀습니다.”

이 답에서 우리가 하지 않는 주장 — 지어내지 않습니다:

  • ❌ “이 서비스를 쓰면 합법이다” — 그런 근거가 어디에도 없습니다. 사용법 문서는 오히려 “제품의 정식 채택 결정이나 콘텐츠 수집·보관·AI 전달 권한까지 승인됐다는 뜻은 아니다”라고 못 박았습니다.
  • ❌ “수집 주체가 제3자라서 Meta 자동수집 약관의 적용을 받지 않는다” — 확인하지 않은 법적 해석입니다. 만들지 않습니다.
  • ❌ “공개 데이터는 자유롭게 써도 된다” — 관련 판례를 해커톤 제출작의 근거로 삼는 것은 부적절하다는 기존 판단을 뒤집지 않습니다.
  • ✅ 우리가 하는 주장은 하나뿐입니다 — “기술적으로 되는 것과 법적으로 되는 것을 구분해서 적었고, 후자는 아직 모른다고 적었다.”
⚠ 미검증 가정 U16 — 이 경로의 약관·법적 지위 법적 검토를 받지 않았습니다. 이 기획서는 이 경로가 적법하다고도 위법하다고도 주장하지 않습니다. 기술 검증으로 대체할 수 없고 사람이 해소해야 하는 항목입니다. 그래도 지금 넣는 이유는 열화 시퀀스가 있기 때문입니다 — U16이 “쓰면 안 된다”로 결론 나도 URL 경로만 빠지고 사진 업로드·자연어로 내려앉으면 제품은 그대로 동작합니다.

예외 하나는 그대로 유지됩니다 — 레퍼런스 계정이 사용자 본인 소유이고 연동이 이미 붙어 있을 때(“내 본계처럼 가고 싶다”)는 공식 API로 읽을 수 있습니다. 본인 계정이므로 U16의 대상도 아닙니다. 단 크리티컬 패스가 아닙니다.

간극 카드 — 문장 형태를 고정한다. 어조는 두 벌이다

자유 서술을 허용하면 근거가 흐려집니다. 그리고 잰 것은 잰 것처럼, 선언은 선언처럼 써야 합니다 — 어느 어조를 쓸지는 레퍼런스가 어느 경로로 들어왔는지가 기계적으로 결정합니다. 사람이 문장을 고르지 않습니다.

(가) 레퍼런스가 URL로 들어왔을 때 — 양쪽 다 실측이다. 측정 어조. “레퍼런스 계정은 {A}인데, 당신은 원래 {B}입니다 — {C}로 제안합니다.” [근거 보기]

예: “레퍼런스 계정은 최근 30건 중 30건에 캡션을 붙였는데, 당신은 최근 12건 중 8건을 캡션 없이 올렸습니다 — 3장에만 붙이는 쪽을 제안합니다.”

(나) 레퍼런스가 사진 업로드·자연어로 들어왔을 때 — 지향 쪽이 선언값이다. 선언 어조. “고르신 결은 {A} 쪽인데, 당신은 원래 {B}입니다 — {C}로 제안합니다.” [근거 보기]

예: “고르신 결은 설명을 붙이는 쪽인데, 당신은 최근 12건 중 8건을 캡션 없이 올렸습니다 — 3장에만 붙이는 쪽을 제안합니다.”
부연: “지향 축에서는 캡션 유무를 잴 수 없어, 결의 선언값과 당신의 실측값을 비교했습니다.”

(가)가 새로 생긴 것이지 (나)가 폐기된 것이 아닙니다. 문제였던 것은 잰 적 없는 값을 잰 것처럼 쓰는 것이었고, URL 경로에서는 실제로 쟀으므로 (가)가 날조가 아닌 것입니다. 사진·자연어 경로에서는 (나)를 그대로 씁니다.
  • [근거 보기]를 펼치면 양쪽 원본이 나옵니다 — 지향 쪽은 레퍼런스 게시물의 원본 링크(URL 경로) / 업로드 파일 ID / 자연어 원문, 현재 쪽은 게시물 permalink 또는 수집된 원본 링크 / 내 업로드 파일 ID.
  • 버튼은 2개 — 지향대로 가기 / 원래대로 가기. 아무것도 안 누르면 제안값이 유지됩니다. 최종 저자는 사용자입니다(P1).
  • 간극 카드는 최대 3개만 띄웁니다(간극이 큰 순). 타이틀을 1개만 내는 것과 같은 이유 — 고르는 부담을 새로 만들지 않습니다.

지향 입력이 없을 때 — 제품이 방향을 먼저 제안한다

프리셋과 갈라지는 한 문장.

조사가 찾은 빈 자리에 축 전환으로 새로 열린 자리를 더해 3개를 고릅니다. 순서가 중요합니다 — 심사장 발화 순서 그대로입니다.

1순위
W1
사진 N장의 캐러셀 내부 서사 순서 — 무엇을 하는 제품인지

① 조사 범위 내에서 아무도 하지 않습니다. Gride는 프로필 그리드 한정, aiCarousels·Gamma는 텍스트 슬라이드 한정 ② 우리의 1번 출력과 정확히 같습니다 ③ 심사장에서 1초에 이해됩니다 — “사진 15장 넣으면 순서가 나옵니다” ④ 트리거 T1·T2가 이 기능을 직접 부릅니다.

근거 강도: 본 조사 범위에서 반례를 찾지 못했습니다. 전수 조사는 아니므로 “조사 범위 내 미발견”이 정확한 표현입니다.

2순위
W4
지향과 현재의 간극을 메운다 — 왜 프리셋이 아닌지

① 가장 강한 반론에 대한 유일한 답입니다. W1·W3는 둘 다 “그거 프리셋 아닌가”에 답하지 못합니다 — 순서 규칙도 비움 규칙도 프리셋이 흉내낼 수 있습니다 ② 검증 가능한 명제로 번역됩니다 — “같은 레퍼런스 + 같은 사진, 다른 사람 → 다른 결과”(검증 V3). 차별점이 슬로건이 아니라 테스트가 됩니다 ③ 구현 비용이 새 기능이 아닙니다 — F1 안의 합성 규칙 하나입니다 ④ 이름 ‘결’의 실질이 이것입니다.

3순위
W3
“설명 없음”을 정당한 결과로 내놓기 — 왜 믿을 만한지

① 조사한 모든 캡션 도구가 캡션을 반드시 생성합니다 ② 구현 비용이 거의 0 — 새 모델이 아니라 출력 규칙 하나입니다 ③ 기능이 아니라 신뢰 장치입니다. 다 채우지 않는 AI는 P1을 말이 아니라 행동으로 증명합니다.

격하 이유: 비움 판단의 근거는 “내 기존 게시물 12건 중 8건이 캡션 없음”인데 이건 CurrentProfile에서만 나옵니다. 보정축이 비면 비움을 “권장”할 근거가 사라지고 “선택”으로 낮아집니다 → W3는 W4에 종속된 차별점이므로 W4 뒤에 섭니다.

흡수
W2
시각 아이덴티티 + 언어 아이덴티티가 한 프로필로 — W4에 흡수. 독립 차별점으로 세지 않는다

축이 둘이 되면서 W2의 내용이 W4 안으로 들어갔습니다 — 시각 축은 주로 지향에서, 언어 축은 사실상 현재에서만 나오므로 “시각과 언어가 한 프로필”이라는 말이 곧 “두 축을 합성한다”는 말이 됩니다. 따로 세면 차별점이 4개가 되어 MVP 규율과 충돌합니다. 구현은 그대로 하고, 설명은 W4 안에서 합니다.

심사장 발화 순서 — 이 순서여야 한다 ① “사진 넣으면 순서를 정해준다”(W1) → ② “그런데 레퍼런스대로만 가지 않는다. 원래 당신 방식과 어긋나면 말해준다”(W4) → ③ “그래서 필요 없는 자리는 비운 채로 준다”(W3).

W4를 먼저 말하면 “무슨 제품인지”가 안 잡히고, W4를 빼면 W1·W3가 각각 프리셋과 게으름으로 읽힙니다.

가장 강한 반론에 정면으로 답한다

“그거 스타일 프리셋 아닌가?” — 지금 1순위 반론

실제로 위험이 높은 반론입니다. 막연한 걱정이 아닌 이유 셋 — ① 주축의 입력이 얇을 수 있습니다(레퍼런스 사진에서 뽑히는 건 시각 특성 몇 개뿐) ② 시각 특성 몇 개로 순서를 짜면 그건 규칙 기반 배치이고, 규칙 = 프리셋입니다 ③ 보정축이 선택이라 실제로 자주 비어 있을 것입니다 → 이 항목은 뒤집혔습니다(바로 아래).

③이 뒤집혔습니다 — 이 반론이 실제로 약해진 유일한 지점입니다. 보정축이 필수 입력이 되면서 이제 대부분의 세션에 CurrentProfile이 있습니다. “입력이 같으면 출력이 같다”는 프리셋의 정의가 기본값에서부터 깨집니다. 다만 조건이 하나 붙습니다 — 1차 타깃에게 필수 입력을 실제로 받아내는 것은 URL이 아니라 사진 업로드이므로, 업로드 마찰을 3장까지 낮추지 못하면 이 개선은 서류상으로만 존재합니다.

이번 개정으로 ①이 무효가 된 게 아니라 방향이 갈렸습니다. 레퍼런스가 URL로 들어오면 캡션까지 실측되므로 주축이 “시각 특성 몇 개”로 얇아지지는 않습니다. 사진·자연어 경로에서는 원문 그대로 성립합니다. 그리고 URL 경로에는 반대 방향의 압력이 새로 생깁니다 — 주축이 두꺼워질수록 보정축이 묻힙니다. 검증 V3가 이미 실패 원인 ③으로 “레퍼런스가 강하면 모든 결과가 레퍼런스로 수렴할 수 있다”를 적어 뒀는데, URL 경로는 정확히 레퍼런스를 강하게 만드는 변경입니다. 즉 이 리스크의 총량이 내려갔다고 말할 수 없습니다.

답 = 보정축. 논증 3단:

  1. 프리셋은 입력이 같으면 출력이 같다. 보정축이 있으면 같은 레퍼런스 + 같은 사진 + 다른 사람 = 다른 결과입니다. 이건 취향 주장이 아니라 반증 가능한 명제이고, 검증 V3가 그대로 이 명제의 실험입니다.
  2. 언어 축에서 “당신이 원래 어떻게 썼는가”는 CurrentProfile에서만 나온다. 프리셋은 캡션 습관을 가질 수 없습니다. (이전 문장은 “언어 축은 CurrentProfile이 유일 소스다”였습니다. 레퍼런스가 URL로 들어오면 레퍼런스의 언어도 실측되므로 “유일”은 깨졌습니다 — 정직하게 좁혀 씁니다. 깨지지 않은 부분이 논증의 핵심입니다: 레퍼런스의 문체를 아무리 잘 재도 사용자 본인의 문체는 거기서 안 나옵니다.)
  3. 간극 카드는 프리셋이 원리적으로 못 내는 출력이다. 프리셋은 “당신은 원래 이렇습니다”를 말할 수 없습니다. 사용자를 모르기 때문입니다. 이 한 문장이 제품과 필터 앱을 가릅니다.

    4. 대신 반대쪽 리스크가 새로 생겼습니다 — “그거 그냥 내 피드 요약 아닌가”. 지향 입력이 없는 기본 경로에서 제품이 CurrentProfile만 보고 방향을 제안하면, 결과가 “원래 하던 대로”로 수렴할 수 있습니다. 대응은 셋입니다.

    • 제안이 “당신은 원래 {A}입니다”에서 멈추지 않습니다. “이번 사진들은 {B}가 많으니 {C} 쪽으로”까지 갑니다 — 이번 사진이 제안에 들어가는 것이 요약과 제안을 가릅니다(03절).
    • 지향 입력이 한 번 클릭으로 열려 있습니다 — [다른 방향으로 바꾸기]. 덮어쓰기가 언제든 가능하다는 것이 이 구조의 핵심입니다.
    • ⚠️ 검증 안 됨 — U18이 정확히 이 리스크의 검증입니다. 앞 반론의 대응이 V3으로 검증되듯, 이 대응은 V2 확장분으로 검증됩니다. 검증 전에 “제품이 방향을 제안합니다”를 강점으로 주장하지 않습니다.

최소 요구선 — 보정축 수집 마찰을 “사진 3장”까지 낮추고(10장을 요구하면 아무도 안 합니다), 보정축이 결과를 실제로 바꾸는 것이 화면에서 보여야 합니다(배너의 [내 사진 올리기]를 누르면 결과가 눈앞에서 갱신되고 무엇이 바뀌었는지 간극 카드로 뜹니다).

⚠ 미검증 — 이 대응이 실제로 먹히는지는 아직 확인되지 않았습니다 “보정축이 있으니 프리셋이 아니다”는 논증이지 검증이 아닙니다. U9·U10과 검증 V3가 그 검증입니다. 검증 전에 발표에서 “프리셋이 아닙니다”를 사실처럼 주장하지 않습니다.

비공개 계정 읽기읽을 수 있는 경로가 0개입니다. 수집 서비스는 비공개 피드를 지원 대상으로 삼지 않고, 공식 API는 프로페셔널 전환을 요구하는데 전환하면 계정이 공개로 바뀝니다. “지금은 아니다”가 아니라 “수단이 없다”이므로, 할 수 있는 일은 UI에 정직하게 적는 것뿐입니다(03절).
수집 결과의 세션 간 보관 / 계정별 캐시계정/로그인이 없으므로(맨 위 줄) 누구의 캐시인지 식별할 수 없습니다. 그리고 이미지 URL을 영구 주소로 취급하지 않습니다. 보관하는 것은 데모용 사전 수집 스냅샷 하나뿐이고 보관 기간을 정해 적습니다(03절 D5·D7).

V2 · 코드 0줄

핵심 가설 — “설명 없음”을 사용자가 결과로 받아들이는가

틀리면: W3가 무너집니다. 우리는 “캡션을 안 써주는 캡션 도구”가 되고 차별점이 W1 하나만 남습니다. U1이 직접 걸린 지점입니다.

어떻게: 같은 사진 6장으로 결과 화면 목업 두 벌. A = 6장 전부 캡션 있음. B = 2장만 캡션, 4장은 “비움(권장)” 카드 + 근거 문구. 순서를 사람마다 뒤섞어 보여주고 “둘 중 어느 쪽을 그대로 올리시겠어요? 왜요?”를 묻습니다. 5명 × 5분, 목업 이미지 두 장이면 됩니다.

통과 기준: 5명 중 3명 이상이 B를 고르거나, 고르지 않더라도 “비움 카드에 근거가 붙어 있어서 납득됐다”고 말합니다. 실패 신호: “빈 칸이 성의 없어 보인다”가 과반.

추가 한 벌 (필수, 5분) — U18 검증: 같은 사진 6장에 대해 D = 지향 입력 없이 제품이 제안한 결과(제안 카드 포함)를 만들어 보여주고 묻습니다 — “이 제안, 원래 하시던 거랑 뭐가 다른가요?” 통과 기준: 5명 중 3명 이상이 차이를 한 문장으로 말합니다. “똑같은데요”가 과반이면 “내 피드 요약”으로의 전락이 현실화된 것이고, 제안 문장에서 “이번 사진들은 {B}가 많으니” 부분의 비중을 올리는 것을 게이트에 올립니다.

선택 추가 (5분): 같은 B에서 근거 문구만 지운 C를 보여줍니다(= 보정축이 빈 경우). B > C면 “보정축이 없으면 권장하지 않고 선택으로 낮춘다”는 규칙이 옳다는 근거가 되고, B ≈ C면 근거 문구가 장식이라는 뜻이라 W3의 설계 비용을 다시 봐야 합니다.

  6. 03절의 “레퍼런스 계정은 대부분 공개다”는 추론이지 조사 결과가 아닙니다. 주축 1순위가 실제로 열려 있다는 판단이 이 추론 위에 서 있고, 아직 확인하지 않았습니다.
  7. “보정축이 있으니 프리셋이 아니다”는 논증이지 검증이 아닙니다.
  8. 합성 규칙 — 특히 기울기 0.7과 간극 경계값 — 은 근거 없는 설계 선택입니다. 구현 단계에서 정하고, 정해진 뒤에도 튜닝 노브로 남깁니다.
  9. 해커톤 득점 전략은 자체 가정 루브릭 기반입니다. 공식 심사 기준은 확인 실패 상태(U8)이며, 확보 즉시 교체합니다.
  10. 제품명 결 GYEOL의 상표·도메인·앱스토어 중복은 여전히 미확인입니다. 외부 노출 전에 사람이 확인해야 합니다.

타깃 행동 근거

  • 캐릿 — 본계/부계 문화

    한국 20대는 하나의 SNS에서 2개 이상 계정을 운영하는 것이 일반적이며, “현생이 되어버린 본계”를 벗어나 찐 일상을 올릴 부계를 따로 만드는 흐름이 보고됩니다. 상세 분류는 페이월 구간이라 부계 유형 분류는 확보하지 못함

  • Instagram 공식 도움말 — 계정 전환

    인스타그램은 앱 하나에서 최대 5개 계정 전환을 공식 지원합니다. 복수 계정 운영이 예외가 아니라 지원되는 기본 동작이라는 근거.

  • Later — photo dump 트렌드

    한 번에 5~10장을 캐주얼하게 올리는 포맷의 정의. 이 층의 행동이 “여러 장 → 순서 문제”를 자연 발생시키는 경로.

  • 캐러셀 20장 확대

    앱 안에서 캐러셀이 20장까지 늘면서 “몇 번째에 뭘 놓을까” 문제가 커졌습니다.

  • 게시 후 캐러셀 재정렬 허용 (2026-03-24)

    “올린 뒤 후회”가 흔하다는 방증. 3자 블로그 기준 · Meta 공식 공지는 직접 확인 실패

캡션 문화와 배치 규칙

  • 한국어 AI 문체 탐지 신호

    한국어 사용자 커뮤니티에 “AI가 쓴 글은 티가 난다”는 문체 탐지 감각이 명시적으로 공유되고 있습니다. 지목되는 신호: 쉼표 과다, “이처럼 / 또한 / 이를 통해 / 이러한 / 마침내”. 이 단어들을 F3의 출력 금지 목록에 넣은 근거입니다.

  • 한국어 피드 배치 실무 규칙

    “메인 컬러 2 + 포인트 컬러 1을 미리 정하고, 꽉 찬 컷과 여백 있는 컷, 클로즈업과 풀샷을 번갈아 배치” — 배치 규칙이 이미 구체적으로 유통되고 있습니다. F2의 시각 리듬 축이 여기서 나왔습니다.

  • photo dump 캡션 조언

    “이모지 하나, 날짜, 한 줄이 긴 문단보다 낫다.” 시장의 조언과 도구의 동작이 어긋나 있다는 W3의 근거.

이 절에서 확실하게 말할 수 있는 것은 이것뿐입니다: 한국어 사용자는 AI 문체를 식별하는 감각이 이미 있고, 피드 배치 규칙을 수동으로 학습·적용하고 있습니다. 즉 “AI가 대신 써주는 것”에는 저항이 있고, “배치를 도와주는 것”에는 이미 수요가 있습니다.

플랫폼 제약 — “안 하는 것”의 근거

  • Meta — 콘텐츠 게시 API

    게시 API는 Instagram professional account를 요구하고 instagram_business_basic, instagram_business_content_publish 권한이 필요합니다. 부가 사실: 게시 API는 캐러셀을 10장으로 제한합니다 — 앱 안에서는 20장이 가능한데도 그렇습니다.

  • Meta — App Review 요건

    Advanced Access는 App Review를 통해서만 부여되며 비즈니스 인증, 라이브 모드 앱, 개인정보처리방침, 데이터 삭제 경로, 스크린캐스트를 요구합니다. 승인은 수일~수주, 첫 제출 반려가 흔합니다. 자동 게시를 MVP에서 뺀 결정의 근거입니다.

  • Meta — 자동 데이터 수집 약관

    서면 허가 없는 자동 수집을 금지하고 scraper·bot·crawler를 명시 열거합니다. 우리가 직접 크롤러를 짜지 않는 근거이며, 이 판정은 이번 개정에서도 바뀌지 않았습니다. 제3자 수집 서비스를 쓰는 것이 이 약관 판단을 바꾸는지는 확인하지 못했습니다(U16).

인스타 URL 수집 — 이번 개정의 근거 출처 확인

  • 실행 기록 — 공개 계정 1건 수집 결과

    상태 SUCCEEDED · 게시물 100개(캐러셀 71 / 영상 27 / 단일 2) · 캡션 100개 전부 존재 · 캐러셀 내부 미디어 291개 · 이미지 표본 9개 전부 HTTP 200 · 약 74.6초 / $0.27. “레퍼런스 계정 URL 입력 제외” 결정을 철회한 유일한 근거이며, 표본은 이 1건뿐입니다(U11~U15).

  • Apify Instagram Scraper · 가격표

    Meta 공식 API가 아닌 제3자 수집 서비스입니다. 구독 할인 없는 요율은 결과 1,000개당 $2.70. 비공개 피드는 지원 대상이 아닙니다. 실측 문서는 “제품의 정식 채택 결정이나 콘텐츠 수집·보관·AI 전달 권한까지 승인됐다는 뜻은 아니다”라고 명시했습니다.

경쟁 서비스 — 직접 확인한 것

  • Gride / Feedloom (App Store)

    가장 위험한 인접 경쟁자. 내 기존 사진 스타일을 학습해 배치하지만 캡션 기능이 스토어 기능 목록에 언급조차 없고, 다루는 순서는 프로필 그리드지 캐러셀 내부가 아닙니다.

  • Later · Preview App

    둘 다 스케줄링·그리드 미리보기 중심이며 1인 브랜드/소상공인을 정조준합니다. 캐러셀 내부 순서를 다루지 않습니다.

  • aiCarousels · Gamma 캐러셀 가이드

    캐러셀 서사 구조(“첫 슬라이드가 스와이프를 벌고 마지막이 결론을 찍는다”)를 언어화해 유통시키고 있지만, 텍스트 슬라이드 도구입니다 — 내가 찍은 사진을 입력으로 받지 않습니다. 검색 결과 스니펫으로만 확인 · 본문 미검증

확인 실패 — 이 문서가 쓰지 않는 것

⚠ 아래는 확인하지 못했으므로 이 문서에서 수치로 인용하지 않습니다
  • 글로벌 SMM(소셜미디어 관리) 시장 규모 — Grand View Research 원문이 403으로 직접 검증 실패. 검색 스니펫에 숫자가 있지만 이 기획서는 그 수치를 쓰지 않습니다.
  • 대회 공식 일정·자격·제출물 형식·심사 기준·배점·상금 — 대상 페이지가 클라이언트 사이드 렌더링이라 WebFetch·curl로 본문을 읽지 못했습니다(U8). 사람이 브라우저로 직접 열람하거나 주최측 공지를 확보해야 합니다. 현재 쓰는 루브릭은 자체 가정 루브릭이며 공식 기준 확보 즉시 교체합니다.
  • 한국 캡션 문화의 정량 데이터 — U1·U2가 여기 걸려 있습니다. 사용자 테스트로만 확인 가능합니다.
  • Canva AI 캡션 생성기 — 페이지 403으로 직접 확인 실패.
  • 경쟁사 앱을 직접 설치·사용하지 않았습니다. 공개 문서·스토어 설명 기준이므로, 문서에 안 적힌 기능이 실제로 있을 수 있습니다.
  • W1이 “아무도 안 한다”는 것은 전수 조사가 아닙니다. 정확한 표현은 “조사 범위 내 미발견”입니다.
